Correcting Sharpe Ratios for Autocorrelation: The Lo Factor in Practice

2026-11-10 Quant Trading

The Sharpe ratio's standard error formula assumes i.i.d. returns. That assumption is almost always false for real strategies: smoothed marks, overlapping holding periods, illiquid positions, and momentum effects all leave a lag-1 autocorrelation in the return series. When returns are autocorrelated, the effective sample size is smaller than the nominal one, and significance tests fire far too often. With rho = 0.2, a nominal 5% test rejects the null at 18–25% in simulation. That is not a small calibration error; it is the difference between "maybe real" and "coin flip."

The fix is cheap: correct the Sharpe ratio by the Lo factor before you run any significance test.

The Lo Adjustment

Lo (2002) derives the asymptotic variance of the Sharpe estimator under serial dependence. For an AR(1)-style dependence with lag-1 autocorrelation rho, the corrected Sharpe is:

SR_corrected = SR * sqrt((1 - rho) / (1 + rho))

Interpretation:

  • rho > 0 (smoothed or persistent returns): the factor is below 1, so the corrected Sharpe is lower. The raw number overstated the risk-adjusted edge because the sample carried less independent information than its length suggested.
  • rho < 0 (mean-reverting returns): the factor is above 1. Negative autocorrelation means the strategy recovers from drawdowns faster than an i.i.d. process would, so the effective sample is larger.
  • rho = 0: factor is 1, no change.

The rule I use: apply the correction whenever |rho| > 0.1. Below that threshold the adjustment is within noise of the estimate itself, and applying it adds churn without information. Above it, ignoring the correction is a methodological error, not a modeling choice.

A note on the general form

The (1 - rho)/(1 + rho) factor is the AR(1) special case. For q-th order dependence, the full Lo variance uses a weighted sum of autocorrelations:

eta = 1 + 2 * sum_{k=1}^{q} ((q - k) / q) * rho_k
SR_corrected = SR * sqrt(eta)   # note: eta in the variance, so sqrt(eta) on the ratio

For most daily-frequency strategies, lag-1 dominates and the closed form above is enough. Use the general form when you have overlapping windows (e.g., 5-day returns sampled daily), where lag-k dependence out to k = 4 is structural, not noise.

Computing the Autocorrelation

Do not eyeball this from a chart. Compute it, and compute it on the return series you actually test, not on cumulative PnL. Cumulative PnL is a random walk under the null and will show high autocorrelation regardless of the strategy.

import numpy as np
import pandas as pd

def lag1_autocorr(returns: pd.Series) -> float:
    """Lag-1 autocorrelation of a return series, NaN-safe."""
    r = returns.dropna()
    if len(r) < 3:
        return float("nan")
    x = r.to_numpy(dtype=float)
    x = x - x.mean()
    denom = np.dot(x, x)
    if denom == 0.0:
        return 0.0
    return float(np.dot(x[1:], x[:-1]) / denom)

def acf(returns: pd.Series, nlags: int = 5) -> np.ndarray:
    """Sample ACF up to nlags, using the same denominator for all lags."""
    x = returns.dropna().to_numpy(dtype=float)
    x = x - x.mean()
    denom = np.dot(x, x)
    return np.array([np.dot(x[k:], x[:-k]) / denom for k in range(nlags + 1)])

Two practical checks before you trust the number:

  1. Sample size. A lag-1 estimate on 60 observations has a standard error near 1/sqrt(60) ≈ 0.13. A raw rho of 0.08 there is indistinguishable from zero. Require at least ~250 observations before acting on the correction, and treat estimates near the 0.1 threshold as borderline.
  2. Regime stability. Compute rho on rolling windows. A strategy whose autocorrelation flips sign across regimes is telling you the dependence is not a stable structural feature, and the correction is itself unstable. Report the range, not just the full-sample value.

Implementing the Adjustment

Keep the correction in one place so every downstream test uses the same number.

from dataclasses import dataclass

@dataclass(frozen=True)
class SharpeReport:
    sr_raw: float
    rho: float
    factor: float
    sr_corrected: float
    applied: bool

def lo_adjust(sr_raw: float, rho: float, threshold: float = 0.1) -> SharpeReport:
    if abs(rho) <= threshold:
        return SharpeReport(sr_raw, rho, 1.0, sr_raw, applied=False)
    # guard against |rho| -> 1, where the factor explodes or collapses
    rho = float(np.clip(rho, -0.99, 0.99))
    factor = np.sqrt((1.0 - rho) / (1.0 + rho))
    return SharpeReport(sr_raw, rho, factor, sr_raw * factor, applied=True)

def annualized_sharpe(returns: pd.Series, periods_per_year: int = 252) -> float:
    r = returns.dropna()
    sd = r.std(ddof=1)
    if sd == 0 or len(r) < 2:
        return float("nan")
    return float(r.mean() / sd * np.sqrt(periods_per_year))

Then wire it into your evaluation path:

def evaluate(returns: pd.Series, periods_per_year: int = 252) -> SharpeReport:
    sr = annualized_sharpe(returns, periods_per_year)
    rho = lag1_autocorr(returns)
    return lo_adjust(sr, rho)

The SharpeReport object carries both numbers and a flag. Log the flag. If a strategy's headline Sharpe only survives because the correction was never applied, you want that visible in the report, not buried in a notebook.

Correcting the standard error, not just the point estimate

The point estimate correction is what people remember, but the test is where the false positives come from. The corrected Sharpe has standard error approximately:

SE(SR) ≈ sqrt((1 + SR^2 / 2) / n) * sqrt((1 + rho) / (1 - rho))

Note the direction: positive autocorrelation inflates the standard error by the same factor that deflates the point estimate. Both effects push you toward "not significant," which is the honest conclusion. A quick t-statistic:

def sharpe_tstat(sr: float, rho: float, n: int) -> float:
    rho = float(np.clip(rho, -0.99, 0.99))
    se = np.sqrt((1.0 + 0.5 * sr**2) / n) * np.sqrt((1.0 + rho) / (1.0 - rho))
    return sr / se

Run this on raw and corrected Sharpe with the same rho and the same n. If the raw version clears 3.0 and the corrected one does not, the strategy does not clear 3.0.

Case Study: rho = -0.33

Negative autocorrelation is the less-discussed case, and it is worth walking through because the correction moves the number up, which invites overconfidence.

Suppose a mean-reversion strategy on a liquid futures contract shows an annualized Sharpe of 1.40 over 500 daily observations, with lag-1 autocorrelation of -0.33. That is a large negative value. Check it against the ACF before proceeding:

r = strategy_returns  # pd.Series of daily returns
print(acf(r, nlags=5))
# [1.0, -0.33, 0.11, -0.04, 0.02, -0.01]

The pattern — strong lag-1, weak lag-2, near-zero beyond — is consistent with a genuine AR(1) mean-reverting component rather than an artifact. Now apply the correction:

factor = sqrt((1 - (-0.33)) / (1 + (-0.33)))
       = sqrt(1.33 / 0.67)
       = sqrt(1.985)
       ≈ 1.409

SR_corrected = 1.40 * 1.409 ≈ 1.97

A Sharpe of 1.40 becomes 1.97. That is a 41% uplift, and it is legitimate under the AR(1) model: negative dependence means each observation carries more independent information than its index suggests, so the effective sample is larger than 500.

But the standard error moves too:

n = 500
print(sharpe_tstat(1.40, -0.33, n))  # raw, corrected SE
print(sharpe_tstat(1.97, -0.33, n))  # corrected SR, corrected SE

With rho = -0.33, the SE factor is sqrt(0.67 / 1.33) ≈ 0.71, so the standard error shrinks by about 29%. The t-statistic rises, but not by the 41% the point estimate suggests. The two adjustments partially offset. This is the honest reading: negative autocorrelation helps, but less than the headline correction implies.

Two caveats on negative rho specifically:

  • Transaction costs. Strong negative autocorrelation at daily frequency often reflects bid-ask bounce or a strategy that is harvesting microstructure noise. The corrected Sharpe is arithmetically right but economically fragile — the dependence may vanish the moment you widen spreads or add latency.
  • Sign instability. Mean-reversion regimes flip. Compute rho on rolling 126-day windows; if it swings between -0.4 and +0.1, the full-sample -0.33 is an average of different processes and the correction is not meaningful.

Why This Kills Overfitted Strategies

The autocorrelation correction is the single most common missing step in strategy evaluation, and it interacts badly with multiple testing.

Consider a grid search over 200 parameter combinations. You keep the best in-sample Sharpe. Two things then compound:

  1. Selection bias. The maximum of 200 noisy Sharpe estimates is far above the true Sharpe of any of them. This is the deflated Sharpe problem: the expected maximum grows with the number of trials.
  2. Autocorrelation inflation. Each candidate's test statistic is computed under the independence assumption. If the underlying returns have rho = 0.2, each test's false-positive rate is 18–25% instead of 5%. You are not selecting from 200 candidates at a 5% error rate; you are selecting from 200 candidates at roughly a 20% error rate, and then taking the maximum.

The result is a strategy that looks significant at p < 0.01 on the raw numbers and is pure noise. The autocorrelation correction does not fix selection bias on its own, but it is a prerequisite. Deflating a Sharpe that was never corrected for dependence deflates the wrong quantity.

A minimal evaluation harness that handles both:

def evaluate_grid(results: pd.DataFrame, n_trials: int, periods_per_year: int = 252):
    """
    results: columns ['returns'] as pd.Series, one row per candidate.
    Returns a frame with raw and corrected Sharpe, t-stats, and a
    deflation threshold based on the number of trials.
    """
    rows = []
    for _, row in results.iterrows():
        r = row["returns"]
        rep = evaluate(r, periods_per_year)
        n = int(r.dropna().shape[0])
        t_corr = sharpe_tstat(rep.sr_corrected, rep.rho, n)
        rows.append({
            "sr_raw": rep.sr_raw,
            "rho": rep.rho,
            "sr_corrected": rep.sr_corrected,
            "t_corrected": t_corr,
            "n": n,
        })
    out = pd.DataFrame(rows)

    # Expected max of n_trials standard normals, as a rough selection threshold.
    # For a rigorous version use the deflated Sharpe ratio (Bailey & Lopez de Prado).
    from scipy.stats import norm
    expected_max_z = norm.ppf(1.0 - 1.0 / (2.0 * n_trials)) if n_trials > 1 else 0.0
    out["selection_threshold_t"] = expected_max_z
    out["passes"] = out["t_corrected"] > expected_max_z
    return out

The expected_max_z line is a crude proxy for the multiple-testing hurdle, not a substitute for a proper deflated Sharpe. It is there to make the point concrete: once you correct for rho, the bar the best candidate must clear goes up, and the number of candidates that clear it goes down. Usually to zero, which is the correct answer for most grid searches.

Practical Checklist

  • Compute rho on returns, not cumulative PnL, and require at least ~250 observations.
  • Apply the Lo factor when |rho| > 0.1; clip rho away from ±1 before taking the square root.
  • Correct the standard error as well as the point estimate. Both matter, and they push in the same direction for positive rho.
  • Check the ACF out to lag 5. A single dominant lag-1 is a clean AR(1) story; a long tail means you need the general form or a different model.
  • Compute rho on rolling windows. Unstable autocorrelation makes the correction unstable, and that instability is itself a finding.
  • Never deflate an uncorrected Sharpe. Fix the dependence first, then account for the number of trials.
