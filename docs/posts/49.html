自动化系统监控面板：用Python搭建简单的健康看板

2026-10-19 系统运维

跑量化策略的系统，最怕的不是策略亏钱，而是策略悄悄挂了你还不知道。数据源断了、API 超时了、定时任务没跑、缓存写爆了——这些问题不会主动报警，只会让你在复盘时发现“咦，昨天怎么没信号”。

这篇文章搭一个轻量级的健康看板，不依赖 Prometheus + Grafana 那套重型方案，纯 Python 搞定：数据采集、状态判定、Web 展示、定时刷新，一个文件能跑起来。适合个人或小团队的量化系统。

整体设计

看板要展示五类信息：

  • 模块运行状态：数据采集、策略计算、下单执行等核心模块是否存活
  • 最近任务执行结果：定时任务的成功/失败/耗时
  • API 连接状态：交易所、行情源、数据库的连通性
  • 缓存使用情况：Redis 或本地缓存的内存占用、命中率
  • 错误统计：最近一段时间的异常数量与分类

架构很简单：一个采集器负责收集指标写入内存/JSON 文件，一个 Flask 应用读取并渲染页面，前端用 JS 定时轮询刷新。不引入数据库，不引入消息队列，保持最小依赖。

collector.py  →  metrics.json  →  app.py (Flask)  →  浏览器轮询刷新

数据采集层

先定义统一的数据结构。所有指标都收敛成一个 dict，方便序列化和前端渲染：

# collector.py
import json
import time
import psutil
import redis
import requests
from datetime import datetime
from pathlib import Path

METRICS_FILE = Path("metrics.json")

def check_module(name, pid=None):
    """检查进程是否存活。pid 为 None 时视为外部模块，由心跳文件判定"""
    if pid is None:
        return {"name": name, "status": "unknown", "detail": "no pid"}
    try:
        proc = psutil.Process(pid)
        return {
            "name": name,
            "status": "alive" if proc.is_running() else "dead",
            "detail": f"cpu={proc.cpu_percent():.1f}% mem={proc.memory_info().rss // 1024 // 1024}MB"
        }
    except psutil.NoSuchProcess:
        return {"name": name, "status": "dead", "detail": "process not found"}

def check_api(name, url, timeout=3):
    """HTTP 探活，记录响应时间"""
    start = time.time()
    try:
        r = requests.get(url, timeout=timeout)
        cost = (time.time() - start) * 1000
        ok = r.status_code < 400
        return {
            "name": name,
            "status": "ok" if ok else "error",
            "detail": f"{r.status_code} {cost:.0f}ms"
        }
    except Exception as e:
        cost = (time.time() - start) * 1000
        return {"name": name, "status": "error", "detail": f"{type(e).__name__} {cost:.0f}ms"}

def check_cache(host="localhost", port=6379):
    """Redis 内存与命中率"""
    try:
        r = redis.Redis(host=host, port=port, socket_timeout=2)
        info = r.info("memory")
        stats = r.info("stats")
        hits = stats.get("keyspace_hits", 0)
        misses = stats.get("keyspace_misses", 0)
        total = hits + misses
        hit_rate = hits / total * 100 if total else 0
        return {
            "status": "ok",
            "used_mb": round(info["used_memory"] / 1024 / 1024, 2),
            "peak_mb": round(info["used_memory_peak"] / 1024 / 1024, 2),
            "hit_rate": round(hit_rate, 1),
            "keys": r.dbsize()
        }
    except Exception as e:
        return {"status": "error", "detail": str(e)}

这里用 psutil 判断进程存活，requests 做 API 探活，redis-py 读缓存指标。三个库都是常规依赖，pip install psutil requests redis 即可。

任务执行记录

定时任务的执行结果，最省事的做法是让任务本身写一条记录到 JSON Lines 文件，采集器只负责读取和聚合：

# 任务侧调用：记录一次执行
def log_task(name, success, duration, error=None):
    record = {
        "name": name,
        "success": success,
        "duration": round(duration, 2),
        "error": error,
        "ts": datetime.now().isoformat()
    }
    with open("tasks.jsonl", "a") as f:
        f.write(json.dumps(record) + "\n")

# 采集侧：读取最近 N 条，聚合成统计
def summarize_tasks(path="tasks.jsonl", recent=50):
    p = Path(path)
    if not p.exists():
        return {"recent": [], "stats": {}}
    lines = p.read_text().strip().splitlines()[-recent:]
    records = [json.loads(l) for l in lines if l.strip()]
    total = len(records)
    failed = sum(1 for r in records if not r["success"])
    return {
        "recent": records[-10:],  # 前端只展示最近 10 条
        "stats": {
            "total": total,
            "failed": failed,
            "fail_rate": round(failed / total * 100, 1) if total else 0,
            "avg_duration": round(sum(r["duration"] for r in records) / total, 2) if total else 0
        }
    }

错误统计

错误同样走 JSONL，按类型聚合：

def summarize_errors(path="errors.jsonl", window_hours=24):
    p = Path(path)
    if not p.exists():
        return {"count": 0, "by_type": {}}
    cutoff = time.time() - window_hours * 3600
    by_type = {}
    count = 0
    for line in p.read_text().strip().splitlines():
        try:
            rec = json.loads(line)
        except json.JSONDecodeError:
            continue
        ts = datetime.fromisoformat(rec["ts"]).timestamp()
        if ts < cutoff:
            continue
        count += 1
        etype = rec.get("type", "Unknown")
        by_type[etype] = by_type.get(etype, 0) + 1
    return {"count": count, "by_type": by_type}

汇总入口

把所有采集函数串起来，写成一个快照：

def collect_all():
    snapshot = {
        "ts": datetime.now().isoformat(),
        "modules": [
            check_module("data_feed", pid=12345),
            check_module("strategy_engine", pid=12346),
            check_module("order_executor", pid=12347),
        ],
        "apis": [
            check_api("exchange_rest", "https://api.example.com/ping"),
            check_api("market_data", "https://quote.example.com/health"),
        ],
        "cache": check_cache(),
        "tasks": summarize_tasks(),
        "errors": summarize_errors(),
    }
    METRICS_FILE.write_text(json.dumps(snapshot, ensure_ascii=False, indent=2))
    return snapshot

if __name__ == "__main__":
    print(json.dumps(collect_all(), ensure_ascii=False, indent=2))

实际使用时，这个 collect_all() 挂到 cron 或 APScheduler 里，每 30 秒跑一次，把结果写入 metrics.json。采集和展示解耦，页面永远读的是最近一次快照，不会因为探活超时把页面卡住。

Web 展示层

用 Flask 做后端，一个路由返回 JSON，一个路由渲染页面：

# app.py
import json
from pathlib import Path
from flask import Flask, jsonify, render_template_string

app = Flask(__name__)
METRICS_FILE = Path("metrics.json")

@app.route("/api/metrics")
def api_metrics():
    if not METRICS_FILE.exists():
        return jsonify({"error": "no data"}), 503
    return jsonify(json.loads(METRICS_FILE.read_text()))

@app.route("/")
def index():
    return render_template_string(PAGE_HTML)

if __name__ == "__main__":
    app.run(host="0.0.0.0", port=5000)

前端不引框架，原生 JS 轮询 /api/metrics，每 10 秒刷新一次，根据状态字段染色。核心是三个渲染函数：模块/API 状态用色块，任务表用表格，错误用柱状。

定时刷新与部署

采集和展示分开跑，两个进程各自独立：

# 采集器：每 30 秒写一次快照
while true; do python collector.py >> collector.log 2>&1; sleep 30; done

# Web 服务
python app.py

如果不想用 shell 循环，用 APScheduler 更规范：

from apscheduler.schedulers.blocking import BlockingScheduler
from collector import collect_all

sched = BlockingScheduler()
sched.add_job(collect_all, "interval", seconds=30)
sched.start()

部署上，个人用 nohup 或 systemd 起两个服务即可。前端轮询间隔 10 秒，采集间隔 30 秒，页面最多看到 40 秒前的数据，对健康监控来说完全够用。如果希望更实时，把采集间隔调到 10 秒，代价是多几次 API 探活请求。

几个实践细节

探活别打真实业务接口。 给每个外部服务配一个轻量 /ping 或 /health 端点，别用下单或查询接口探活，避免产生副作用和限流。

状态判定要有阈值。 比如 API 响应时间超过 1 秒就标黄，连续 3 次失败才标红，避免单次网络抖动误报。可以在采集器里维护一个滑动窗口：

from collections import deque
_api_history = {}

def check_api_with_threshold(name, url, fail_threshold=3):
    result = check_api(name, url)
    hist = _api_history.setdefault(name, deque(maxlen=fail_threshold))
    hist.append(result["status"] == "error")
    if all(hist) and len(hist) == fail_threshold:
        result["status"] = "error"
        result["detail"] += " (连续失败)"
    return result

错误日志要带类型。 写 errors.jsonl 时，type 字段用异常类名（TimeoutError、ConnectionError），聚合出来的分布才有意义。
