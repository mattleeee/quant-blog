为什么我放弃了守护进程，改用Windows计划任务跑Python脚本

2026-08-04 定时任务

公司电脑装了深信服（Sangfor）安全软件，这玩意对后台进程的监控极其严格。我原本用 supervisord 挂着几个量化数据采集脚本，结果发现每天凌晨脚本都会神秘消失。排查了三天，最后定位到是安全软件拦截了守护进程创建的子进程。这让我彻底放弃了在 Windows 上跑守护进程的想法，转而全面拥抱 Windows 任务计划程序（Task Scheduler）。

问题现象：脚本莫名其妙消失

场景是这样的：我在一台 Windows 10 办公机上部署了三个 Python 脚本，分别负责：

  • 拉取分钟级 K 线数据并写入 SQLite
  • 计算技术指标并更新到 MySQL
  • 定时发送交易信号到企业微信

我用了 supervisord 来管理这三个进程，配置了自动重启和日志输出。部署后前两周一切正常，但从第三周开始，每天凌晨 2 点到 4 点之间，supervisord 会报告子进程退出，但退出码是 0（正常退出），而且重启后依然会在同一时间段被杀掉。

我一开始以为是代码问题，加了各种异常捕获和日志，但毫无收获。直到我手动在凌晨 2 点守着，才发现是深信服弹了一个拦截通知——它把 python.exe 创建的子进程当成了可疑行为，直接 kill 掉了。

排查过程：从代码到系统安全策略

排查过程分了三步：

  1. 检查 Python 代码：确认没有 sys.exit() 或未捕获异常，日志显示正常执行到 time.sleep()。
  2. 检查系统事件日志：在“应用程序”日志里发现了 Application Error 和 Windows Error Reporting，但没具体信息。
  3. 检查安全软件日志：深信服控制台显示“进程行为拦截”，目标进程是 python.exe，动作是“创建子进程”。

最后确认：深信服对“守护进程创建子进程”这一行为有默认拦截策略，尤其是当父进程是 python.exe 且子进程是 cmd.exe 或另一个 python.exe 时，命中概率极高。

方案对比：守护进程 vs 任务计划程序

对比项 守护进程 (supervisord/nssm) Windows 任务计划程序
进程隔离 父进程创建子进程，易被安全软件拦截 每个任务独立运行，无父子进程关系
自启动 需要配置服务，依赖登录会话 系统级任务，开机即启动
定时触发 需自己写循环或 cron 表达式 原生支持分钟/小时/每天/事件触发
日志输出 统一日志文件 任务历史记录 + 可自定义重定向
失败重启 自动重启 可配置“失败后重新启动”策略
资源占用 常驻内存，约 50-100MB 按需启动，运行完即退出

对于量化脚本来说，任务计划程序有天然优势：脚本本来就是定时跑，不是常驻服务。用守护进程反而是一种资源浪费，还容易触发安全策略。

实战：用任务计划程序跑 Python 脚本

我最终用 schtasks 命令行和 PowerShell 脚本实现了一套完整的定时任务管理方案。

1. 创建基础定时任务

假设脚本路径是 D:\scripts\market_data.py，Python 环境是 C:\Python39\python.exe，每天 9:30 运行一次：

schtasks /Create /TN "QuantData" /TR "C:\Python39\python.exe D:\scripts\market_data.py" /SC DAILY /ST 09:30 /RU SYSTEM /RL HIGHEST

注意点： - /RU SYSTEM 用系统账户运行，避免登录会话问题 - /RL HIGHEST 提升权限，防止安全软件误判 - 如果脚本需要网络访问，确保 SYSTEM 账户有网络权限

2. 配置失败重试和日志

任务计划程序默认失败后不重试，需要手动设置。用 PowerShell 修改任务设置：

$task = Get-ScheduledTask -TaskName "QuantData"
$task.Settings.ExecutionTimeLimit = "PT2H"  # 最长运行2小时
$task.Settings.RestartCount = 3              # 失败重试3次
$task.Settings.RestartInterval = "PT5M"      # 每次间隔5分钟
Set-ScheduledTask -InputObject $task

日志重定向可以写在命令里：

schtasks /Create /TN "QuantData" /TR "cmd /c C:\Python39\python.exe D:\scripts\market_data.py >> D:\logs\market_data.log 2>&1" /SC DAILY /ST 09:30 /RU SYSTEM

3. 动态传参和状态检查

如果脚本需要根据日期或参数运行，可以用环境变量或命令行参数。例如每天跑不同策略：

# market_data.py
import sys
import datetime

strategy = sys.argv[1] if len(sys.argv) > 1 else "default"
today = datetime.date.today().isoformat()
print(f"[{today}] Running strategy: {strategy}")

任务命令里传参：

schtasks /Create /TN "QuantData" /TR "C:\Python39\python.exe D:\scripts\market_data.py momentum" /SC DAILY /ST 09:30 /RU SYSTEM

检查任务运行状态：

schtasks /Query /TN "QuantData" /V /FO LIST

4. 用 Python 管理任务

如果你有多个任务需要管理，可以用 subprocess 封装一个管理脚本：

# task_manager.py
import subprocess

def create_task(task_name, script_path, schedule_time, args=None):
    python_path = r"C:\Python39\python.exe"
    script_args = " ".join(args) if args else ""
    cmd = f"schtasks /Create /TN {task_name} /TR \"{python_path} {script_path} {script_args}\" /SC DAILY /ST {schedule_time} /RU SYSTEM /RL HIGHEST"
    result = subprocess.run(cmd, shell=True, capture_output=True, text=True)
    print(result.stdout)
    if result.returncode != 0:
        print(f"Error: {result.stderr}")

def enable_task(task_name):
    subprocess.run(f"schtasks /Change /TN {task_name} /ENABLE", shell=True)

if __name__ == "__main__":
    create_task("QuantData", r"D:\scripts\market_data.py", "09:30", ["momentum"])
    create_task("QuantSignal", r"D:\scripts\signal_generator.py", "10:00")

踩过的坑

坑 1：SYSTEM 账户访问不了网络共享路径

如果你的脚本读取 \\server\share\data.csv，SYSTEM 账户可能没有权限。解决办法是改用 /RU DOMAIN\username 并指定密码：

schtasks /Create /TN "QuantData" /TR "..." /SC DAILY /ST 09:30 /RU "MYDOMAIN\zhangsan" /RP "password"

坑 2：任务计划程序不加载用户环境变量

脚本里用 os.getenv("API_KEY") 可能拿不到值。解决方式是在脚本里显式加载 .env 文件：

from dotenv import load_dotenv
load_dotenv(r"D:\config\secrets.env")

坑 3：Python 脚本闪退但任务显示“运行中”

如果脚本崩溃但进程没退出，任务会一直显示“正在运行”。需要设置 ExecutionTimeLimit（上面已经提到），同时脚本里加超时保护：

import signal

def timeout_handler(signum, frame):
    raise TimeoutError("Script timed out")

signal.signal(signal.SIGALRM, timeout_handler)
signal.alarm(3600)  # 1小时超时

坑 4：多个任务同时跑导致资源竞争

比如两个脚本同时写同一个 SQLite 数据库。解决办法是加文件锁：

import filelock

lock = filelock.FileLock(r"D:\data\market_data.lock")
with lock:
    # 写数据库操作
    pass

坑 5：日志文件无限增长

重定向到日志文件后，如果不做轮转，磁盘会爆。用 Python 的 logging.handlers.RotatingFileHandler 解决：

import logging
from logging.handlers import RotatingFileHandler

handler = RotatingFileHandler(
    r"D:\logs\market_data.log",
    maxBytes=10 * 1024 * 1024,  # 10MB
    backupCount=5
)
logging.basicConfig(handlers=[handler], level=logging.INFO)

最终效果

切换后，脚本再也没有被安全软件拦截过。任务计划程序在系统层面运行，不依赖用户登录状态，即使我下班锁屏，脚本照样跑。而且资源占用比守护进程低得多——脚本跑完就退出，不占内存。

如果你也在 Windows 上跑量化脚本，且遇到了类似的进程被拦截问题，强烈建议试试任务计划程序。它本身就是 Windows 原生的任务调度工具，稳定性和兼容性都比第三方守护进程好得多。
