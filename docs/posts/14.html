Python多线程扫描实战：5线程ThreadPoolExecutor并行处理

2026-08-14 Python自动化

量化策略的运维中，扫描全市场币种的技术指标是高频操作。假设你有200个交易对，每个需要计算RSI、MACD、布林带等指标，串行跑一遍可能要几分钟。这个速度在实盘信号触发场景下不可接受。

本文分享一个实战方案：用ThreadPoolExecutor开5个线程并行扫描，将耗时压缩到原来的1/4左右。代码可直接改造使用。

为什么是5个线程？

线程数不是越多越好。Python的GIL（Global Interpreter Lock）限制了CPU密集型任务的多核利用，但对I/O密集型任务（网络请求、文件读写）效果显著。我们的扫描场景主要是网络请求行情数据 + 本地计算，属于混合型。

选择5个线程的依据：

  1. 交易所API限频：多数交易所的REST接口限制每秒请求次数（如Binance的1200次/分钟）。5个线程并发请求，单线程每秒约4-5次请求，5线程约20-25次/秒，远低于限频阈值。
  2. GIL影响可控：计算指标时虽然受GIL限制，但网络等待时间占比高，GIL竞争不严重。
  3. 错误隔离：线程数少，单个线程异常不会拖垮整个进程。
  4. 实测经验：5线程在性能和稳定性之间平衡较好。超过10线程，收益递减且限频风险增加。

ThreadPoolExecutor核心用法

concurrent.futures.ThreadPoolExecutor是Python 3.2+的标准库，封装了线程池的创建、任务提交和结果收集。核心方法：

  • submit(fn, *args, **kwargs)：提交单个任务，返回Future对象
  • map(fn, *iterables)：批量提交，按顺序返回结果
  • shutdown(wait=True)：关闭线程池，等待所有任务完成

先看一个最小示例：

from concurrent.futures import ThreadPoolExecutor, as_completed
import time

def scan_symbol(symbol):
    """模拟扫描单个币种的技术指标"""
    time.sleep(1)  # 模拟网络请求和计算
    return f"{symbol} 扫描完成"

symbols = [f"BTCUSDT", "ETHUSDT", "BNBUSDT", "SOLUSDT", "XRPUSDT"]

# 串行版本
start = time.time()
for s in symbols:
    print(scan_symbol(s))
print(f"串行耗时: {time.time() - start:.2f}s")

# 5线程并行版本
start = time.time()
with ThreadPoolExecutor(max_workers=5) as executor:
    futures = [executor.submit(scan_symbol, s) for s in symbols]
    for future in as_completed(futures):
        print(future.result())
print(f"5线程耗时: {time.time() - start:.2f}s")

输出对比清晰：串行5秒，5线程约1秒。as_completed按完成顺序返回结果，适合处理耗时不均的任务。

实战：全市场技术指标扫描

下面是一个完整的实战代码，扫描币安现货所有USDT交易对，计算RSI和布林带，筛选出超卖或超买的币种。

import requests
import pandas as pd
import numpy as np
from concurrent.futures import ThreadPoolExecutor, as_completed
from datetime import datetime
import time

# 配置
BASE_URL = "https://api.binance.com"
SYMBOLS_URL = f"{BASE_URL}/api/v3/ticker/price"
KLINE_URL = f"{BASE_URL}/api/v3/klines"
MAX_WORKERS = 5
INTERVAL = "15m"  # K线周期
LIMIT = 100  # 获取100根K线

def get_all_symbols():
    """获取所有USDT交易对"""
    resp = requests.get(SYMBOLS_URL, timeout=10)
    data = resp.json()
    return [item["symbol"] for item in data if item["symbol"].endswith("USDT")]

def fetch_klines(symbol):
    """获取单个币种的K线数据"""
    params = {
        "symbol": symbol,
        "interval": INTERVAL,
        "limit": LIMIT
    }
    resp = requests.get(KLINE_URL, params=params, timeout=10)
    if resp.status_code != 200:
        raise Exception(f"{symbol} 请求失败: {resp.status_code}")
    data = resp.json()
    if len(data) < 50:
        return None  # 数据不足，跳过

    df = pd.DataFrame(data, columns=[
        "open_time", "open", "high", "low", "close", "volume",
        "close_time", "quote_volume", "count", "taker_buy_vol",
        "taker_buy_quote", "ignore"
    ])
    df["close"] = df["close"].astype(float)
    df["high"] = df["high"].astype(float)
    df["low"] = df["low"].astype(float)
    return df

def calculate_rsi(df, period=14):
    """计算RSI指标"""
    delta = df["close"].diff()
    gain = delta.where(delta > 0, 0.0)
    loss = -delta.where(delta < 0, 0.0)
    avg_gain = gain.ewm(alpha=1/period, min_periods=period).mean()
    avg_loss = loss.ewm(alpha=1/period, min_periods=period).mean()
    rs = avg_gain / avg_loss
    rsi = 100 - (100 / (1 + rs))
    return rsi.iloc[-1]

def calculate_bollinger(df, period=20, std_dev=2):
    """计算布林带，返回最新值"""
    mid = df["close"].rolling(period).mean()
    std = df["close"].rolling(period).std()
    upper = mid + std_dev * std
    lower = mid - std_dev * std
    return {
        "mid": mid.iloc[-1],
        "upper": upper.iloc[-1],
        "lower": lower.iloc[-1],
        "close": df["close"].iloc[-1]
    }

def scan_symbol(symbol):
    """扫描单个币种，返回分析结果"""
    try:
        df = fetch_klines(symbol)
        if df is None:
            return None

        rsi = calculate_rsi(df)
        boll = calculate_bollinger(df)

        # 判断信号
        signal = "NORMAL"
        if rsi < 30 and boll["close"] < boll["lower"]:
            signal = "超卖"
        elif rsi > 70 and boll["close"] > boll["upper"]:
            signal = "超买"

        return {
            "symbol": symbol,
            "close": boll["close"],
            "rsi": round(rsi, 2),
            "boll_upper": round(boll["upper"], 4),
            "boll_lower": round(boll["lower"], 4),
            "signal": signal
        }
    except Exception as e:
        print(f"[ERROR] {symbol}: {e}")
        return None

def main():
    print(f"[{datetime.now().strftime('%H:%M:%S')}] 开始获取交易对列表...")
    symbols = get_all_symbols()
    print(f"共 {len(symbols)} 个USDT交易对")

    results = []
    start_time = time.time()

    # 5线程并行扫描
    with ThreadPoolExecutor(max_workers=MAX_WORKERS) as executor:
        future_to_symbol = {
            executor.submit(scan_symbol, symbol): symbol 
            for symbol in symbols
        }

        completed = 0
        for future in as_completed(future_to_symbol):
            symbol = future_to_symbol[future]
            result = future.result()
            completed += 1

            if completed % 20 == 0:
                elapsed = time.time() - start_time
                print(f"进度: {completed}/{len(symbols)} | 耗时: {elapsed:.1f}s")

            if result:
                results.append(result)

    elapsed = time.time() - start_time
    print(f"\n扫描完成，共 {len(results)} 个有效结果，总耗时: {elapsed:.2f}s")

    # 筛选信号
    oversold = [r for r in results if r["signal"] == "超卖"]
    overbought = [r for r in results if r["signal"] == "超买"]

    print(f"\n超卖信号 ({len(oversold)}个):")
    for r in oversold[:10]:
        print(f"  {r['symbol']}: 收盘 {r['close']}, RSI {r['rsi']}, 下轨 {r['boll_lower']}")

    print(f"\n超买信号 ({len(overbought)}个):")
    for r in overbought[:10]:
        print(f"  {r['symbol']}: 收盘 {r['close']}, RSI {r['rsi']}, 上轨 {r['boll_upper']}")

if __name__ == "__main__":
    main()

线程安全注意事项

多线程环境下，共享资源需要特别处理。上面代码中，每个线程只操作自己的局部变量（df、result），没有共享可变状态，这是最安全的设计。

实际项目中你可能遇到以下场景：

1. 共享缓存

如果多个线程读写同一个字典缓存，需要加锁：

import threading

cache = {}
cache_lock = threading.Lock()

def get_cached_data(symbol):
    with cache_lock:
        if symbol in cache:
            return cache[symbol]
    # 缓存未命中，执行请求
    data = fetch_data(symbol)
    with cache_lock:
        cache[symbol] = data
    return data

2. 日志输出

print在Python 3中是线程安全的（内部有GIL保护），但多线程交替输出会混乱。建议使用logging模块：

import logging
logging.basicConfig(level=logging.INFO, format='%(asctime)s - %(threadName)s - %(message)s')

# 在线程函数中
logging.info(f"{symbol} 扫描完成")

3. 全局计数器

使用threading.Lock保护递增操作：

counter = 0
counter_lock = threading.Lock()

def update_counter():
    global counter
    with counter_lock:
        counter += 1

性能对比实测

在一台4核8线程的Linux服务器上，扫描Binance现货全部约300个USDT交易对，获取100根15分钟K线并计算RSI和布林带：

线程数 总耗时 相对串行加速比
1（串行） 128.5s 1.0x
3 48.2s 2.7x
5 31.6s 4.1x
8 28.9s 4.4x
10 29.5s 4.4x

关键结论：

  • 5线程相比串行，加速约4倍，耗时从2分钟降到30秒
  • 5线程到8线程，提升不明显，说明瓶颈已从CPU转移到网络I/O
  • 10线程反而略有下降，可能是线程切换开销增加

线程数选择建议：

  • 纯I/O密集型（大量网络请求）：线程数 = 2 * CPU核心数 或更高
  • 混合型（网络+计算）：线程数 = CPU核心数 + 1 到 2倍
  • 有API限频：线程数 = 限频阈值 / 单线程请求频率

异常处理与重试机制

生产环境必须有异常处理和重试。上面的代码已经捕获了单线程内的异常，但网络请求偶尔会超时，建议增加重试：

import time
from functools import wraps

def retry(max_retries=3, delay=1):
    """简单的重试装饰器"""
    def decorator(func):
        @wraps(func)
        def wrapper(*args, **kwargs):
            for attempt in range(max_retries):
                try:
                    return func(*args, **kwargs)
                except Exception as e:
                    if attempt == max_retries - 1:
                        raise
                    time.sleep(delay * (attempt + 1))  # 指数退避
            return None
        return wrapper
    return decorator

@retry(max_retries=3, delay=2)
def fetch_klines(symbol):

    pass

扩展：异步替代方案

如果追求更高并发，可以考虑asyncio + aiohttp实现异步I/O，单线程即可处理数百个并发请求。但异步代码复杂度较高，调试困难。对于扫描这类简单任务，ThreadPoolExecutor是性价比最高的方案。

踩坑记录

  1. 线程数过多导致限频：Binance的API限频是按IP计算的，5个线程并发请求，每秒钟约20次请求，安全。但如果你同时运行多个策略，总请求量会叠加，需要全局控制。

  2. DataFrame线程安全：pandas的DataFrame不是线程安全的。每个线程独立创建自己的DataFrame，不要共享。上面的代码中，fetch_klines返回独立的df，线程间无交集。

  3. 内存占用：300个币种，每个100根K线，DataFrame内存占用不大（约几十MB）。但如果扩大到全市场5000+个币种，建议边扫描边释放，不要全部存内存。

  4. 异常导致线程崩溃：as_completed遍历时，如果某个Future抛异常，会直接中断主流程。务必在scan_symbol内部捕获所有异常并返回None。

本文的完整代码可以直接运行，替换成自己的数据源和指标计算逻辑即可。多线程扫描的核心思路是：将独立的任务拆分给多个线程，用ThreadPoolExecutor统一管理生命周期，用as_completed实时获取结果。线程数5是一个经验值，实际项目中可以根据API限频和机器配置调整。
