从WPS灵犀迁移到Windows计划任务的全过程

2026-08-07 定时任务

WPS灵犀的守护进程被深信服安全软件拦截后，定时任务全部哑火。排查发现，灵犀的调度器依赖后台常驻进程，而深信服会将其识别为可疑行为并强制终止。与其和杀软斗智斗勇，不如直接把定时任务迁移到Windows计划任务（Task Scheduler）上——系统原生、无守护进程、稳定可靠。

本文记录完整迁移过程，包括任务分析、PowerShell包装、计划任务创建、执行验证和历史数据迁移。

迁移前的任务盘点

先摸清灵犀里到底跑了哪些定时任务。打开WPS灵犀的任务列表，逐条记录：

任务名 触发频率 执行内容 依赖环境
数据备份 每天 02:00 backup.py Python 3.10 + 虚拟环境
行情抓取 每30分钟 fetch_quotes.py Python + 数据库连接
日志清理 每周日 03:00 cleanup_logs.py 无特殊依赖
报表生成 每天 09:30 report.py Python + pandas

关键点：所有任务都是Python脚本，灵犀只是充当调度器。迁移的本质就是换掉调度器，脚本本身不需要改动。

编写PowerShell包装脚本

Windows计划任务直接执行Python脚本时，工作目录和日志输出容易出问题。统一用PowerShell脚本做包装，处理三件事：

  1. 切换到脚本所在目录
  2. 激活虚拟环境
  3. 捕获输出和错误日志

创建 run_python_task.ps1：

param(
    [Parameter(Mandatory=$true)]
    [string]$ScriptPath,

    [string]$PythonEnv = "C:\Users\quant\.venv\Scripts\python.exe",

    [string]$LogDir = "C:\logs\tasks"
)

# 确保日志目录存在
if (!(Test-Path $LogDir)) {
    New-Item -ItemType Directory -Path $LogDir -Force | Out-Null
}

# 获取脚本所在目录
$ScriptDir = Split-Path -Parent $ScriptPath
$ScriptName = [System.IO.Path]::GetFileNameWithoutExtension($ScriptPath)
$Timestamp = Get-Date -Format "yyyyMMdd_HHmmss"
$LogFile = Join-Path $LogDir "$ScriptName_$Timestamp.log"

# 切换到脚本目录
Set-Location $ScriptDir

# 执行Python脚本，记录输出
try {
    $Output = & $PythonEnv $ScriptPath 2>&1
    $ExitCode = $LASTEXITCODE

    # 写入日志
    $LogContent = @"
[$(Get-Date -Format "yyyy-MM-dd HH:mm:ss")] Script: $ScriptPath
[$(Get-Date -Format "yyyy-MM-dd HH:mm:ss")] Exit Code: $ExitCode

Output:
$Output
"@

    $LogContent | Out-File -FilePath $LogFile -Encoding utf8

    if ($ExitCode -ne 0) {
        Write-Error "Script $ScriptName failed with exit code $ExitCode"
        exit $ExitCode
    }

    Write-Host "Task $ScriptName completed successfully"
    exit 0
}
catch {
    $ErrorMessage = $_.Exception.Message
    $ErrorLog = @"
[$(Get-Date -Format "yyyy-MM-dd HH:mm:ss")] Error executing $ScriptPath
Error: $ErrorMessage
"@
    $ErrorLog | Out-File -FilePath $LogFile -Encoding utf8
    Write-Error $ErrorMessage
    exit 1
}

每个任务创建对应的调用脚本，比如 backup_task.ps1：

# 参数：脚本路径, Python环境, 日志目录
.\run_python_task.ps1 -ScriptPath "C:\scripts\backup.py" -PythonEnv "C:\Users\quant\.venv\Scripts\python.exe" -LogDir "C:\logs\tasks"

这样设计的好处：所有任务共用一套日志和错误处理逻辑，后续加新任务只需创建一行调用脚本。

创建Windows计划任务

用 schtasks 命令行工具创建计划任务，比图形界面更可控，也方便批量操作。

创建每日任务（数据备份）

schtasks /Create /TN "QuantTasks\DataBackup" /TR "powershell.exe -ExecutionPolicy Bypass -File C:\scripts\backup_task.ps1" /SC DAILY /ST 02:00 /RU SYSTEM /RL HIGHEST

参数说明： - /TN：任务名称，用 \ 分目录 - /TR：要执行的命令，注意用引号包裹 - /SC DAILY /ST 02:00：每天凌晨2点触发 - /RU SYSTEM：以SYSTEM账户运行，避免权限问题 - /RL HIGHEST：最高权限

创建周期任务（行情抓取）

schtasks /Create /TN "QuantTasks\FetchQuotes" /TR "powershell.exe -ExecutionPolicy Bypass -File C:\scripts\fetch_quotes_task.ps1" /SC MINUTE /MO 30 /RU SYSTEM /RL HIGHEST

/SC MINUTE /MO 30 表示每30分钟执行一次。

创建每周任务（日志清理）

schtasks /Create /TN "QuantTasks\CleanupLogs" /TR "powershell.exe -ExecutionPolicy Bypass -File C:\scripts\cleanup_logs_task.ps1" /SC WEEKLY /D SUN /ST 03:00 /RU SYSTEM /RL HIGHEST

/D SUN 指定周日执行。

批量创建脚本

如果任务多，写成PowerShell脚本批量操作：

$tasks = @(
    @{
        Name = "QuantTasks\DataBackup"
        Script = "C:\scripts\backup_task.ps1"
        Schedule = "DAILY"
        Modifier = ""
        Time = "02:00"
        Days = ""
    },
    @{
        Name = "QuantTasks\FetchQuotes"
        Script = "C:\scripts\fetch_quotes_task.ps1"
        Schedule = "MINUTE"
        Modifier = "/MO 30"
        Time = ""
        Days = ""
    },
    @{
        Name = "QuantTasks\CleanupLogs"
        Script = "C:\scripts\cleanup_logs_task.ps1"
        Schedule = "WEEKLY"
        Modifier = "/D SUN"
        Time = "03:00"
        Days = ""
    }
)

foreach ($task in $tasks) {
    $cmd = "schtasks /Create /TN `"$($task.Name)`" /TR `"powershell.exe -ExecutionPolicy Bypass -File $($task.Script)`" /SC $($task.Schedule) $($task.Modifier)"

    if ($task.Time) {
        $cmd += " /ST $($task.Time)"
    }

    if ($task.Days) {
        $cmd += " /D $($task.Days)"
    }

    $cmd += " /RU SYSTEM /RL HIGHEST"

    Write-Host "Creating task: $($task.Name)"
    Invoke-Expression $cmd
}

验证执行结果

创建完任务后，不能干等触发时间，要主动验证。

手动触发任务

schtasks /Run /TN "QuantTasks\DataBackup"

然后查看任务状态：

schtasks /Query /TN "QuantTasks\DataBackup" /V /FO LIST

重点看 上次运行时间、上次结果 和 状态 字段。上次结果 为 0x0 表示成功。

检查日志文件

每个任务执行后都会在 C:\logs\tasks 下生成日志文件，检查内容：

Get-ChildItem "C:\logs\tasks" | Sort-Object LastWriteTime -Descending | Select-Object -First 5

用PowerShell快速验证脚本执行结果：

# 检查最近一次执行是否成功
$latestLog = Get-ChildItem "C:\logs\tasks" | Sort-Object LastWriteTime -Descending | Select-Object -First 1
Select-String -Path $latestLog.FullName -Pattern "Exit Code: 0" -Quiet

处理失败场景

如果任务执行失败，排查顺序：

  1. 任务计划程序里查看 上次结果 错误码
  2. 手动运行PowerShell脚本，看是否能正常执行
  3. 检查Python环境路径是否正确
  4. 确认工作目录是否切换成功

常见的 0x2 错误是系统找不到指定文件，多半是脚本路径或Python路径写错。

历史数据迁移

灵犀的任务执行记录存在它的数据库里，迁移到新环境后，这些历史数据需要保留。

导出灵犀任务记录

灵犀的数据存储位置不固定，一般在用户目录下的 .wps 文件夹。找到任务记录文件：

import json
import os
from datetime import datetime

def export_lingxi_tasks(data_dir="C:\\Users\\quant\\AppData\\Roaming\\wps\\lingxi"):
    """导出灵犀任务执行记录"""
    tasks = []

    # 遍历灵犀数据目录，找到任务记录文件
    for root, dirs, files in os.walk(data_dir):
        for file in files:
            if file.endswith('.json'):
                file_path = os.path.join(root, file)
                try:
                    with open(file_path, 'r', encoding='utf-8') as f:
                        data = json.load(f)
                        if 'tasks' in data:
                            tasks.extend(data['tasks'])
                except Exception as e:
                    print(f"跳过文件 {file_path}: {e}")

    # 导出到标准格式
    export_data = {
        'source': 'wps_lingxi',
        'export_time': datetime.now().isoformat(),
        'tasks': tasks
    }

    with open('lingxi_tasks_export.json', 'w', encoding='utf-8') as f:
        json.dump(export_data, f, ensure_ascii=False, indent=2)

    print(f"导出 {len(tasks)} 条任务记录")

if __name__ == "__main__":
    export_lingxi_tasks()

导入到新任务系统

将导出的JSON转成计划任务的记录格式：

import json
import subprocess
from datetime import datetime

def import_to_scheduler(export_file='lingxi_tasks_export.json'):
    """将灵犀任务记录导入Windows计划任务"""
    with open(export_file, 'r', encoding='utf-8') as f:
        data = json.load(f)

    for task in data['tasks']:
        task_name = f"QuantTasks\\{task['name']}"
        script_path = task.get('script_path', '')
        schedule = task.get('schedule', {})

        # 构建schtasks命令
        cmd = [
            'schtasks', '/Create', '/TN', task_name,
            '/TR', f'powershell.exe -ExecutionPolicy Bypass -File {script_path}'
        ]

        if schedule.get('type') == 'daily':
            cmd.extend(['/SC', 'DAILY', '/ST', schedule.get('time', '00:00')])
        elif schedule.get('type') == 'interval':
            cmd.extend(['/SC', 'MINUTE', '/MO', str(schedule.get('minutes', 30))])
        elif schedule.get('type') == 'weekly':
            cmd.extend(['/SC', 'WEEKLY', '/D', schedule.get('day', 'SUN')])

        cmd.extend(['/RU', 'SYSTEM', '/RL', 'HIGHEST'])

        print(f"创建任务: {task_name}")
        result = subprocess.run(cmd, capture_output=True, text=True)

        if result.returncode == 0:
            print(f"成功: {task_name}")
        else:
            print(f"失败: {task_name} - {result.stderr}")

if __name__ == "__main__":
    import_to_scheduler()

保留执行历史

灵犀里的历史执行记录（比如每次任务执行的成功/失败状态）导出后，存储为CSV方便后续分析：

import csv
import json

def export_execution_history(export_file='lingxi_tasks_export.json', output_csv='task_history.csv'):
    """导出任务执行历史到CSV"""
    with open(export_file, 'r', encoding='utf-8') as f:
        data = json.load(f)

    with open(output_csv, 'w', newline='', encoding='utf-8') as csvfile:
        fieldnames = ['task_name', 'execution_time', 'status', 'duration_seconds', 'error_message']
        writer = csv.DictWriter(csvfile, fieldnames=fieldnames)
        writer.writeheader()

        for task in data['tasks']:
            for execution in task.get('executions', []):
                writer.writerow({
                    'task_name': task['name'],
                    'execution_time': execution.get('timestamp', ''),
                    'status': execution.get('status', ''),
                    'duration_seconds': execution.get('duration', 0),
                    'error_message': execution.get('error', '')
                })

    print(f"历史记录已导出到 {output_csv}")

if __name__ == "__main__":
    export_execution_history()

迁移后的持续监控

迁移完成后，加一个监控任务定期检查所有计划任务是否正常运行：

import subprocess
import datetime

def monitor_tasks():
    """监控计划任务执行状态"""
    tasks = [
        "QuantTasks\\DataBackup",
        "QuantTasks\\FetchQuotes",
        "QuantTasks\\CleanupLogs"
    ]

    issues = []

    for task in tasks:
        # 查询任务状态
        result = subprocess.run(
            ['schtasks', '/Query', '/TN', task, '/V', '/FO', 'LIST'],
            capture_output=True,
            text=True
        )

        if result.returncode != 0:
            issues.append(f"任务 {task} 查询失败")
            continue

        # 解析上次执行结果
        output = result.stdout
        if "上次结果: 0x0" not in output:
            issues.append(f"任务 {task} 上次执行失败")

    if issues:
        # 发送通知（邮件/企业微信等）
        print(f"[{datetime.datetime.now()}] 任务异常: {issues}")
    else:
        print(f"[{datetime.datetime.now()}] 所有任务正常")

if __name__ == "__main__":
    monitor_tasks()

把这个监控脚本也注册为计划任务，每10分钟跑一次，发现问题及时告警。

注意事项

  1. PowerShell执行策略：schtasks 创建任务时用了 -ExecutionPolicy Bypass，确保脚本能执行
  2. 日志轮转：长时间运行后日志文件会很多，定期清理
  3. 时区问题：计划任务按系统本地时间触发，注意服务器时区设置
  4. 杀软兼容：Windows计划任务本身不会被拦截，但如果脚本有敏感操作，可能仍需杀软白名单

迁移完成后，灵犀的定时任务全部在Windows计划任务里运行，不再依赖常驻进程，稳定性明显提升。后续加新任务只需两步：写PowerShell调用脚本 + 执行一条 schtasks 命令。
