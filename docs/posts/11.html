定时任务推送去重机制：5分钟内相同标题跳过

2026-08-11 定时任务

定时任务跑得多了，推送重复是个绕不开的问题。尤其是策略信号、风控告警这类任务，一旦触发重试或者任务本身有延迟，PushPlus 微信推送就可能把同一条消息连推好几遍。今天直接分享一个轻量级的去重方案：5分钟内标题相同则跳过推送。

为什么需要去重

先看个实际场景。假设你有个定时任务每5分钟检查一次行情，条件满足时推送一条信号。某次任务执行到一半网络超时，重试机制触发，同一信号被推送了3次。用户手机上一连收到3条一模一样的微信消息——这体验基本等于骚扰。

更隐蔽的情况是任务本身有延迟。比如某个任务原定10:00执行，但调度器繁忙拖到10:03，期间另一个实例又跑了一次，两条相同信号先后到达。去重机制能直接过滤掉这种重复。

去重逻辑设计

核心思路不复杂：记录每次推送的标题和推送时间，新推送来临时检查相同标题是否在时间窗口内出现过。

设计要点：

  1. 去重键：用标题作为去重键，简单直接。如果需要更细粒度，可以拼接标题+关键参数，但标题通常已经能表达消息类型。
  2. 时间窗口：固定5分钟。窗口大小根据业务调整，信号类任务5分钟够用，告警类可以缩短到1分钟。
  3. 存储方式：内存dict就够了，不需要Redis。定时任务进程是常驻的，dict生命周期和进程一致。
  4. 过期清理：时间窗口外的记录要及时清理，防止dict无限膨胀。

Python代码实现

直接上代码，一个可用的去重推送模块。

import time
import hashlib
import requests
from datetime import datetime, timedelta

class PushDeDuplicator:
    """推送去重器，5分钟内相同标题跳过推送"""

    def __init__(self, window_seconds=300):
        self.window_seconds = window_seconds  # 时间窗口，默认5分钟
        self._records = {}  # 标题 -> 最近推送时间戳

    def _cleanup(self):
        """清理过期记录"""
        now = time.time()
        expired_keys = [
            title for title, ts in self._records.items()
            if now - ts > self.window_seconds
        ]
        for key in expired_keys:
            del self._records[key]

    def should_push(self, title):
        """
        判断是否应该推送
        返回 True 表示可以推送，False 表示重复需要跳过
        """
        self._cleanup()
        now = time.time()

        if title in self._records:
            # 标题存在且未过期，说明是重复推送
            return False

        # 记录本次推送时间
        self._records[title] = now
        return True

    def push_wechat(self, title, content, pushplus_token):
        """带去重的微信推送"""
        if not self.should_push(title):
            print(f"[去重] 跳过重复推送: {title}")
            return False

        # 实际推送逻辑
        url = "http://www.pushplus.plus/send"
        payload = {
            "token": pushplus_token,
            "title": title,
            "content": content,
            "template": "html"
        }

        try:
            resp = requests.post(url, json=payload, timeout=10)
            result = resp.json()
            if result.get("code") == 200:
                print(f"[推送成功] {title}")
                return True
            else:
                print(f"[推送失败] {title}: {result.get('msg')}")
                return False
        except Exception as e:
            print(f"[推送异常] {title}: {str(e)}")
            return False


# 使用示例
if __name__ == "__main__":
    # 初始化去重器，窗口5分钟
    dedup = PushDeDuplicator(window_seconds=300)

    # 模拟推送
    token = "your_pushplus_token_here"

    # 第一次推送，应该成功
    dedup.push_wechat("BTC突破压力位", "价格突破关键阻力，当前价格 50000", token)

    # 1秒后再次推送相同标题，应该被跳过
    time.sleep(1)
    dedup.push_wechat("BTC突破压力位", "价格突破关键阻力，当前价格 50100", token)

    # 不同标题，应该成功
    dedup.push_wechat("ETH放量上涨", "以太坊出现放量突破", token)

时间窗口判断细节

时间窗口的判断逻辑在 should_push 方法里。每次调用先清理过期记录，再检查当前标题是否在记录中。

这里有个细节要注意：清理操作放在判断之前。如果先判断再清理，一个5分钟前的旧记录会导致推送被错误跳过。先清理再判断，保证窗口外的旧记录不会影响新推送。

窗口大小的选择：

  • 5分钟：适合大多数定时任务场景，既能过滤重试导致的重复，又不会因为窗口太长错过新信号。
  • 1分钟：适合高频告警，比如价格异动监控。
  • 10分钟：适合低频策略信号，比如日线级别的突破信号。

实际使用中，把窗口参数化，通过配置调整，不要硬编码。

处理推送失败的情况

上面的代码有个问题：如果推送失败，记录已经写入了，下次相同标题会被跳过。这可能导致消息丢失。

改进方案：

def push_wechat_with_retry(self, title, content, pushplus_token, max_retry=3):
    """推送失败时允许重试，但记录写入延后"""
    for attempt in range(max_retry):
        # 先检查是否重复
        if not self.should_push(title):
            print(f"[去重] 跳过重复推送: {title}")
            return False

        # 执行推送
        success = self._do_push(title, content, pushplus_token)
        if success:
            return True

        # 推送失败，删除记录，允许下次重试
        self._records.pop(title, None)
        print(f"[重试] 第{attempt + 1}次推送失败，准备重试")
        time.sleep(2)

    return False

这样处理的核心逻辑：推送成功才记录时间戳，失败就删除记录。重试时不会因为上次失败而误判为重复。

完整示例：定时任务集成

把去重机制集成到定时任务里，用 schedule 库做个完整示例：

import schedule
import time
from datetime import datetime

# 模拟行情数据
def get_market_data():
    """模拟获取行情，实际场景替换为真实数据源"""
    import random
    return {
        "symbol": "BTC/USDT",
        "price": random.uniform(48000, 52000),
        "change_pct": random.uniform(-3, 3)
    }

def check_and_push():
    """定时检查任务"""
    data = get_market_data()

    # 设置推送阈值
    if data["change_pct"] > 2:
        title = f"{data['symbol']} 涨幅超过2%"
        content = f"""
        <h3>行情异动提醒</h3>
        <p>交易对: {data['symbol']}</p>
        <p>当前价格: {data['price']:.2f}</p>
        <p>涨跌幅: {data['change_pct']:.2f}%</p>
        <p>时间: {datetime.now().strftime('%Y-%m-%d %H:%M:%S')}</p>
        """

        # 使用去重推送
        dedup.push_wechat(title, content, token)
    else:
        print(f"[正常] {data['symbol']} 涨跌幅 {data['change_pct']:.2f}%，不触发推送")

# 初始化去重器
dedup = PushDeDuplicator(window_seconds=300)
token = "your_pushplus_token_here"

# 每5分钟执行一次检查
schedule.every(5).minutes.do(check_and_push)

# 也可以设置多个任务
# schedule.every().hour.at(":00").do(check_and_push)

if __name__ == "__main__":
    print("定时任务启动，按 Ctrl+C 退出")
    while True:
        schedule.run_pending()
        time.sleep(1)

这个示例里，如果行情连续两次触发推送条件，第二次会因为标题相同被去重器拦截。只有行情变化产生新标题（比如涨幅从2.1%变成3.5%，标题可能不变但内容不同），或者5分钟窗口过后，才会再次推送。

实际效果

用这个方案跑了一段时间，效果很明显：

  1. 重试导致的重复推送归零。之前网络抖动时经常连续推3-4条相同消息，现在最多推1条。
  2. 消息可读性提升。用户收到的都是有效信息，不会因为重复消息取消关注。
  3. 代码侵入性小。只需要在原有推送调用处替换成 dedup.push_wechat()，改动量极小。

需要注意的坑：

  • 标题设计要合理。如果标题每次都包含价格数字，去重就失效了。建议标题用固定描述，价格等动态信息放content里。
  • 进程重启会清空记录。内存存储的局限，重启后5分钟内可能重复推送。对大多数场景影响不大，如果要求严格可以持久化到SQLite或文件。

扩展思路

这个去重机制可以进一步扩展：

  • 按用户去重：多个用户订阅相同信号时，每个用户独立去重。
  • 多级窗口：不同重要级别的消息使用不同窗口，比如紧急告警1分钟，普通信号10分钟。
  • 去重计数：记录相同标题被拦截的次数，统计重复率，帮助优化任务逻辑。

去重只是推送环节的一个细节，但直接影响用户体验。定时任务越复杂，这种细节越重要。把基础机制做好，后面加新功能就省心得多。
