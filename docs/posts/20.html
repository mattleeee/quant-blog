深信服安全软件拦截子进程的排查与解决方案

2026-08-22 Python自动化

最近在部署一个自动化交易数据同步脚本时，遇到一个诡异的问题：脚本在本地环境跑得好好的，一旦放到指定服务器上，subprocess 调用的 PowerShell 命令就无响应，进程卡死，日志里没有任何报错。排查了半天，最后发现是深信服（Sangfor）的安全软件在作祟。

这篇文章记录完整的排查过程和解决方案，希望能帮到遇到类似问题的朋友。

问题现象

脚本逻辑很简单：用 subprocess.Popen 调用 PowerShell 脚本拉取数据，然后处理结果。

import subprocess
import time

# 调用 PowerShell 脚本
proc = subprocess.Popen(
    ["powershell.exe", "-ExecutionPolicy", "Bypass", "-File", "fetch_data.ps1"],
    stdout=subprocess.PIPE,
    stderr=subprocess.PIPE,
    text=True,
    encoding="utf-8"
)

# 等待执行完成
try:
    stdout, stderr = proc.communicate(timeout=60)
    print(f"STDOUT: {stdout}")
    print(f"STDERR: {stderr}")
except subprocess.TimeoutExpired:
    print("Timeout: PowerShell 进程无响应")
    proc.kill()

现象描述： - 脚本运行到 subprocess.Popen 后，communicate 一直阻塞，直到 timeout - PowerShell 进程在任务管理器里能看到，但 CPU 和内存占用为 0，像是被挂起 - 手动在命令行运行同样的 PowerShell 命令，一切正常 - 换用 os.system 或 subprocess.run，问题依旧

排查过程

第一步：确认 Python 环境

先排除 Python 环境问题。用最小化代码测试：

import subprocess

# 最简单的子进程测试
result = subprocess.run(
    ["cmd.exe", "/c", "echo hello"],
    capture_output=True,
    text=True,
    timeout=10
)
print(f"Return code: {result.returncode}")
print(f"Output: {result.stdout}")

结果：cmd.exe 也被拦截了，连 echo hello 都执行不了。这说明不是 PowerShell 脚本的问题，而是所有子进程都被拦截。

第二步：检查系统日志

打开 Windows 事件查看器，查看 应用程序 和 安全 日志，发现以下记录：

事件 ID: 4688（进程创建）
进程名称: python.exe
新进程名称: powershell.exe
创建者进程 ID: 0x1234
任务类别: 进程创建

但没有任何失败记录。接着查看深信服终端检测响应平台（EDR）的日志，发现关键信息：

拦截原因: 检测到可疑的父子进程关系
父进程: python.exe
子进程: powershell.exe
策略: 禁止脚本解释器通过父进程创建子进程

第三步：确认拦截源

在深信服安全客户端中，找到 终端防护 → 行为检测 → 隔离策略，可以看到一条规则：

策略名称: 防勒索软件-脚本引擎防护
规则: 禁止 python.exe、wscript.exe、cscript.exe 等解释器创建子进程

这条策略本意是防止勒索软件利用脚本解释器执行恶意命令，但误伤了正常的 Python 自动化调用。

解决方案

方案一：调整深信服策略（推荐）

联系 IT 管理员，在深信服 EDR 管理后台中，按以下步骤操作：

  1. 登录深信服 EDR 控制台
  2. 进入 策略中心 → 终端防护策略 → 行为检测
  3. 找到 "防勒索软件-脚本引擎防护" 策略
  4. 在 白名单 中添加例外规则：
  5. 父进程: python.exe（或具体路径）
  6. 子进程: powershell.exe、cmd.exe 等
  7. 条件: 仅允许信任的脚本路径

如果无法添加白名单，可以临时关闭该策略，但只在测试环境操作，生产环境必须走正规流程。

方案二：绕过子进程调用（临时方案）

如果 IT 部门审批需要时间，可以先用以下方式绕过：

方法1：使用 ctypes 调用 Windows API

import ctypes
import os

# 使用 ShellExecute 替代 subprocess
def run_command_shell_execute(command: str) -> int:
    """
    使用 ShellExecute 执行命令，绕过进程创建拦截
    """
    result = ctypes.windll.shell32.ShellExecuteW(
        None,      # hwnd
        "open",    # lpOperation
        command,   # lpFile
        None,      # lpParameters
        None,      # lpDirectory
        1          # nShowCmd (SW_SHOWNORMAL)
    )
    # 返回值 > 32 表示成功
    return result

方法2：通过计划任务执行

import subprocess

def run_via_scheduled_task(task_name: str, command: str):
    """
    创建 Windows 计划任务来执行命令，计划任务创建的进程不受解释器拦截策略影响
    """
    # 创建计划任务
    create_cmd = (
        f'schtasks /Create /TN "{task_name}" /TR "{command}" '
        f'/SC ONCE /ST 00:00 /F'
    )
    subprocess.run(create_cmd, shell=True, check=True)

    # 立即运行
    subprocess.run(f'schtasks /Run /TN "{task_name}"', shell=True, check=True)

    # 删除计划任务
    subprocess.run(f'schtasks /Delete /TN "{task_name}" /F', shell=True, check=True)

方法3：使用 PowerShell 远程执行

import subprocess

def run_powershell_remote(script_path: str):
    """
    通过 WinRM 远程执行 PowerShell，不走本地进程创建链
    """
    ps_command = f"""
    Invoke-Command -ComputerName localhost -ScriptBlock {{
        & "{script_path}"
    }}
    """
    subprocess.run(
        ["powershell.exe", "-Command", ps_command],
        capture_output=True,
        timeout=30
    )

方法4：改用 Python 原生实现

如果子进程只是为了执行简单的文件操作或数据处理，尽量用 Python 原生库替代：

# 替代 PowerShell 的文件复制
import shutil
import os

# 原来用 subprocess 调 PowerShell 复制文件
# subprocess.run(["powershell.exe", "Copy-Item", "src.txt", "dst.txt"])

# 改用 Python 原生
shutil.copy2("src.txt", "dst.txt")

方案三：调整代码架构（长期方案）

从架构层面避免频繁创建子进程：

import subprocess
import threading
import queue

class PersistentProcessManager:
    """
    进程池管理器：复用子进程，减少进程创建频率
    """
    def __init__(self, command: list, max_workers: int = 3):
        self.command = command
        self.processes = queue.Queue()
        self.lock = threading.Lock()

        for _ in range(max_workers):
            self._create_process()

    def _create_process(self):
        proc = subprocess.Popen(
            self.command,
            stdin=subprocess.PIPE,
            stdout=subprocess.PIPE,
            stderr=subprocess.PIPE,
            text=True
        )
        self.processes.put(proc)

    def execute(self, input_data: str) -> str:
        """
        从池中获取进程执行命令，执行完放回池中
        """
        with self.lock:
            if self.processes.empty():
                self._create_process()
            proc = self.processes.get()

        try:
            stdout, stderr = proc.communicate(input=input_data, timeout=30)
            return stdout
        except subprocess.TimeoutExpired:
            proc.kill()
            self._create_process()
            raise
        finally:
            # 检查进程状态，如果还活着就放回池中
            if proc.poll() is None:
                self.processes.put(proc)

这样只需要创建少量子进程，大幅降低触发安全策略的概率。

与 IT 部门沟通的建议

跟 IT 部门沟通时，注意以下几点：

  1. 说明业务场景：明确告知这是量化交易数据同步的自动化脚本，不是恶意程序
  2. 提供证据：给出脚本源码、执行日志、深信服拦截记录
  3. 请求白名单：申请将特定的 Python 脚本路径加入白名单
  4. 提供备选方案：如果无法加白名单，询问是否有其他合规的替代方案

最终解决方案

我们最终通过 IT 部门在深信服 EDR 后台添加了白名单规则：

父进程: D:\Python\python.exe
子进程: powershell.exe, cmd.exe
条件: 命令行包含 "D:\scripts\quant\"

同时在代码中做了优化： - 用 subprocess.run 替代 Popen，减少进程泄漏风险 - 增加超时和重试机制 - 对子进程输出做编码处理，避免乱码

import subprocess
import time
from typing import Tuple

def run_powershell_safe(script_path: str, timeout: int = 30, retries: int = 3) -> Tuple[bool, str]:
    """
    安全的 PowerShell 执行函数，包含超时和重试
    """
    for attempt in range(retries):
        try:
            result = subprocess.run(
                [
                    "powershell.exe",
                    "-ExecutionPolicy", "Bypass",
                    "-NoProfile",
                    "-File", script_path
                ],
                capture_output=True,
                text=True,
                encoding="utf-8",
                errors="replace",
                timeout=timeout
            )

            if result.returncode == 0:
                return True, result.stdout
            else:
                return False, result.stderr

        except subprocess.TimeoutExpired:
            print(f"Attempt {attempt + 1}: Timeout, retrying...")
            time.sleep(2)

    return False, "All retries failed"

# 使用示例
success, output = run_powershell_safe("fetch_data.ps1", timeout=60, retries=3)
if success:
    print(f"执行成功: {output}")
else:
    print(f"执行失败: {output}")

总结

深信服安全软件拦截子进程的问题，核心在于其 "防勒索软件-脚本引擎防护" 策略对解释器创建子进程的限制。解决方案优先级：

  1. 首选：联系 IT 部门添加白名单
  2. 临时：使用 ctypes 或计划任务绕过
  3. 长期：架构层面减少子进程创建频率

遇到类似问题，先看事件查看器和安全软件日志，确认拦截源，再针对性解决。不要盲目改代码，浪费时间。
