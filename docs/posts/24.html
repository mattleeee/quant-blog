系统巡检模块设计：自动检查交易系统健康状态

2026-09-23 Python自动化

交易系统跑起来之后，最怕的不是策略亏钱，而是某个环节悄悄挂了却没人知道。API 断连、行情数据停止更新、磁盘写满、定时任务没跑——这些问题往往在盘中才暴露，那时候已经晚了。

解决办法是写一个系统巡检模块，定时检查各模块健康状态，异常时主动推送告警。这篇文章拆解一下我的实现方案。

一、巡检项设计

巡检不是越多越好，要覆盖关键链路。我的清单如下：

巡检项 检查内容 异常后果
API 连接 交易/行情接口连通性、延迟 无法下单或收不到行情
数据更新 最新 tick/K线时间戳 策略基于过期数据决策
缓存状态 Redis 连接、内存占用、key 数量 状态丢失、读写失败
磁盘空间 各挂载点使用率 日志写不进、数据库崩溃
任务执行 定时任务最近一次执行时间与结果 数据未同步、对账未跑

设计原则：每项检查必须能在 5 秒内返回结果，超时就判定为异常。巡检本身不能拖垮系统。

二、健康判定逻辑

健康状态分三档，避免"非黑即白"导致告警疲劳：

  • OK：正常
  • WARN：需要关注，但不影响交易
  • CRIT：影响交易，必须立即处理

判定逻辑用阈值配置化，不要硬编码：

THRESHOLDS = {
    "api_latency_ms": {"warn": 500, "crit": 2000},
    "data_delay_sec": {"warn": 30, "crit": 120},
    "disk_usage_pct": {"warn": 80, "crit": 90},
    "redis_mem_pct": {"warn": 80, "crit": 95},
    "task_delay_min": {"warn": 10, "crit": 30},
}

统一封装一个判定函数，所有巡检项复用：

def judge(value, thresholds, reverse=False):
    """
    reverse=True 表示值越小越危险（如剩余空间）
    """
    warn, crit = thresholds["warn"], thresholds["crit"]
    if not reverse:
        if value >= crit:
            return "CRIT"
        if value >= warn:
            return "WARN"
    else:
        if value <= crit:
            return "CRIT"
        if value <= warn:
            return "WARN"
    return "OK"

三、各项巡检实现

3.1 API 连接检查

不要只 ping 通就算健康，要真正调用业务接口。比如查一次账户余额或最新行情，测端到端延迟。

import time
import requests

def check_api(url, timeout=3):
    start = time.time()
    try:
        r = requests.get(url, timeout=timeout)
        latency = (time.time() - start) * 1000
        if r.status_code != 200:
            return "CRIT", f"HTTP {r.status_code}", latency
        status = judge(latency, THRESHOLDS["api_latency_ms"])
        return status, f"latency={latency:.0f}ms", latency
    except requests.RequestException as e:
        return "CRIT", f"exception: {e}", -1

3.2 数据更新检查

核心是比对最新数据时间戳和当前时间。数据源可以是数据库、Redis 或本地文件。

import redis
from datetime import datetime

def check_data_freshness(r: redis.Redis, key="last_tick_ts"):
    ts = r.get(key)
    if ts is None:
        return "CRIT", "no tick data"
    delay = time.time() - float(ts)
    status = judge(delay, THRESHOLDS["data_delay_sec"])
    return status, f"delay={delay:.1f}s"

3.3 缓存状态检查

Redis 除了连接性，还要看内存使用率和 key 数量突变。key 数量骤降往往意味着被误清空。

def check_redis(r: redis.Redis, expected_keys_min=100):
    try:
        info = r.info("memory")
        used_pct = info["used_memory"] / info["maxmemory"] * 100 if info.get("maxmemory") else 0
        n_keys = r.dbsize()
        msgs = []
        status = "OK"

        s1 = judge(used_pct, THRESHOLDS["redis_mem_pct"])
        if s1 != "OK":
            status = s1
            msgs.append(f"mem={used_pct:.1f}%")

        if n_keys < expected_keys_min:
            status = "CRIT"
            msgs.append(f"keys={n_keys} < {expected_keys_min}")

        return status, "; ".join(msgs) or "healthy"
    except redis.RedisError as e:
        return "CRIT", f"redis error: {e}"

3.4 磁盘空间检查

用 shutil.disk_usage，遍历所有挂载点。注意排除 tmpfs、overlay 这类临时文件系统。

import shutil
import psutil

def check_disk(mounts=("/", "/data")):
    results = []
    status = "OK"
    for m in mounts:
        try:
            usage = shutil.disk_usage(m)
            pct = usage.used / usage.total * 100
            s = judge(pct, THRESHOLDS["disk_usage_pct"])
            results.append(f"{m}={pct:.1f}%")
            if s == "CRIT":
                status = "CRIT"
            elif s == "WARN" and status != "CRIT":
                status = "WARN"
        except FileNotFoundError:
            results.append(f"{m}=missing")
    return status, "; ".join(results)

3.5 任务执行检查

定时任务用 Redis 或数据库记录每次执行时间。巡检时算距离上次执行的间隔，超过预期周期太多就是异常。

def check_task(r: redis.Redis, task_name, expected_interval_min):
    key = f"task_last_run:{task_name}"
    ts = r.get(key)
    if ts is None:
        return "CRIT", f"{task_name} never ran"
    delay_min = (time.time() - float(ts)) / 60
    # 超过预期周期的 1.5 倍算 WARN，2 倍算 CRIT
    if delay_min > expected_interval_min * 2:
        return "CRIT", f"{task_name} delay={delay_min:.1f}min"
    if delay_min > expected_interval_min * 1.5:
        return "WARN", f"{task_name} delay={delay_min:.1f}min"
    return "OK", f"{task_name} ok"

四、巡检调度与结果聚合

把所有检查项放进一个列表，统一执行。任何一项抛异常都不能影响其他项。

def run_all_checks(r: redis.Redis):
    checks = [
        ("api_trade", lambda: check_api("https://api.example.com/ping")),
        ("api_market", lambda: check_api("https://quote.example.com/ping")),
        ("data_fresh", lambda: check_data_freshness(r)),
        ("redis", lambda: check_redis(r)),
        ("disk", lambda: check_disk()),
        ("task_sync", lambda: check_task(r, "sync_data", 5)),
        ("task_recon", lambda: check_task(r, "reconcile", 60)),
    ]

    report = []
    for name, fn in checks:
        try:
            status, msg = fn()
        except Exception as e:
            status, msg = "CRIT", f"check crashed: {e}"
        report.append({"name": name, "status": status, "msg": msg})
    return report

调度用 APScheduler，每 60 秒跑一次：

from apscheduler.schedulers.blocking import BlockingScheduler

def job():
    r = redis.Redis(host="localhost", port=6379, db=0)
    report = run_all_checks(r)
    handle_report(report)

sched = BlockingScheduler()
sched.add_job(job, "interval", seconds=60)
sched.start()

五、告警推送与降噪

告警最忌讳两件事：漏报和刷屏。我的做法是：

  1. 只在状态变化时推送。上一轮是 OK，这一轮是 CRIT，才发。持续 CRIT 不重复发。
  2. CRIT 立即推，WARN 聚合推。WARN 每 30 分钟汇总一次。
  3. 恢复时也推一条，让人知道问题解决了。

状态用 Redis 存，key 是 alert_state:{check_name}：

def handle_report(report, r: redis.Redis, webhook=None):
    for item in report:
        name, status, msg = item["name"], item["status"], item["msg"]
        state_key = f"alert_state:{name}"
        prev = r.get(state_key)
        prev = prev.decode() if prev else "OK"

        if status != prev:
            r.set(state_key, status)
            if status == "CRIT":
                send_alert(webhook, f"[CRIT] {name}: {msg}")
            elif status == "WARN":
                send_alert(webhook, f"[WARN] {name}: {msg}")
            elif prev in ("CRIT", "WARN") and status == "OK":
                send_alert(webhook, f"[RECOVERED] {name}: {msg}")

推送用企业微信或飞书 webhook 最简单：

def send_alert(webhook, text):
    if not webhook:
        print(f"[ALERT] {text}")
        return
    try:
        requests.post(webhook, json={"msgtype": "text", "text": {"content": text}}, timeout=3)
    except Exception as e:
        print(f"send alert failed: {e}")

六、几个实践细节

1. 巡检自身要有心跳。 巡检脚本挂了没人知道。可以在巡检成功执行后写一个 Redis key，用外部监控（比如另一台机器）检查这个 key 是否更新。

2. 日志要留全量。 告警只推状态变化，但每次巡检结果都要落盘，方便事后复盘。用 logging 写到文件，按天切分。

3. 阈值要能热更新。 别把阈值写死在代码里。可以放 Redis 或配置文件，改完不用重启。

4. 检查项要能单独禁用。 遇到某个检查误报，可以临时关掉，不影响其他项。在 run_all_checks 里加一层配置过滤即可。

5. 时间同步。 数据延迟检查依赖服务器时间准确。部署时确保 NTP 正常，否则会误报。

if __name__ == "__main__":

    logging.basicConfig(
