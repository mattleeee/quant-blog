系统巡检模块设计：自动检查交易系统健康状态

2026-08-26 Python自动化

量化交易系统跑起来容易，稳定运行是另一回事。API断连、数据源停更、磁盘写满、定时任务静默失败——这些问题往往不会第一时间暴露，等到发现时，策略可能已经跑偏了几个小时。

解决思路很简单：写一个巡检模块，定时检查各组件状态，异常时推告警。本文分享这套巡检模块的设计与实现。

巡检项设计

巡检不是漫无目的地到处看，而是针对交易系统的关键路径做定点检查。我归纳了五个核心巡检项：

巡检项 检查内容 异常判定
API连接 行情/交易接口连通性 连续N次请求失败
数据更新 最新K线/ tick 时间戳 数据延迟超过阈值
缓存状态 Redis/内存队列积压量 积压量超过上限
磁盘空间 数据目录、日志目录使用率 使用率 > 85%
任务执行 定时任务最近执行时间 超过执行周期未运行

每个巡检项对应一个检查函数，返回CheckResult对象，包含状态和详情。后续加巡检项只需新增一个函数，不影响整体结构。

健康判定逻辑

单次检查通过不代表系统健康，我用"连续失败次数"作为判定依据。比如API连接，偶尔一次超时可能是网络抖动，连续3次失败才判定为异常。

from enum import Enum
from dataclasses import dataclass
from typing import Optional
import time

class HealthStatus(Enum):
    HEALTHY = "healthy"
    WARNING = "warning"
    CRITICAL = "critical"

@dataclass
class CheckResult:
    item: str
    status: HealthStatus
    detail: str
    timestamp: float = time.time()

每个巡检项维护一个失败计数器，连续失败达到阈值才触发告警。同时设置恢复机制——连续成功2次后重置计数器，避免系统恢复后仍持续告警。

class HealthChecker:
    def __init__(self, fail_threshold: int = 3, recover_threshold: int = 2):
        self.fail_threshold = fail_threshold
        self.recover_threshold = recover_threshold
        self._fail_counts = {}
        self._success_counts = {}
        self._status_map = {}

    def update_status(self, item: str, current_ok: bool) -> HealthStatus:
        if current_ok:
            self._fail_counts[item] = 0
            self._success_counts[item] = self._success_counts.get(item, 0) + 1
            if self._success_counts[item] >= self.recover_threshold:
                self._status_map[item] = HealthStatus.HEALTHY
        else:
            self._success_counts[item] = 0
            self._fail_counts[item] = self._fail_counts.get(item, 0) + 1
            if self._fail_counts[item] >= self.fail_threshold:
                self._status_map[item] = HealthStatus.CRITICAL
            elif self._fail_counts[item] >= 1:
                self._status_map[item] = HealthStatus.WARNING

        return self._status_map.get(item, HealthStatus.HEALTHY)

各巡检项实现

API连接检查

import aiohttp
import asyncio

class APIConnectionCheck:
    def __init__(self, endpoints: list, timeout: float = 5.0):
        self.endpoints = endpoints  # [{"name": "market_api", "url": "https://api.example.com/ping"}]
        self.timeout = timeout

    async def check(self) -> CheckResult:
        failed = []
        for ep in self.endpoints:
            try:
                async with aiohttp.ClientSession() as session:
                    async with session.get(ep["url"], timeout=self.timeout) as resp:
                        if resp.status != 200:
                            failed.append(f"{ep['name']}: HTTP {resp.status}")
            except Exception as e:
                failed.append(f"{ep['name']}: {str(e)[:50]}")

        if not failed:
            return CheckResult("api_connection", HealthStatus.HEALTHY, "all endpoints ok")
        return CheckResult("api_connection", HealthStatus.CRITICAL, "; ".join(failed))

数据更新检查

数据更新检查的核心是判断最新数据的时间戳是否足够新。以K线数据为例：

class DataFreshnessCheck:
    def __init__(self, db_conn, symbols: list, max_delay_seconds: int = 60):
        self.db = db_conn
        self.symbols = symbols
        self.max_delay = max_delay_seconds

    def check(self) -> CheckResult:
        stale_symbols = []
        for symbol in self.symbols:
            latest_time = self.db.get_latest_kline_time(symbol)
            if latest_time is None:
                stale_symbols.append(f"{symbol}: no data")
                continue
            delay = time.time() - latest_time
            if delay > self.max_delay:
                stale_symbols.append(f"{symbol}: {delay:.0f}s delay")

        if not stale_symbols:
            return CheckResult("data_freshness", HealthStatus.HEALTHY, "all symbols fresh")
        return CheckResult("data_freshness", HealthStatus.CRITICAL, "; ".join(stale_symbols))

缓存状态检查

Redis 队列积压是常见问题。生产者和消费者的处理速度不匹配，积压量会持续增长，最终导致内存溢出或数据延迟。

import redis

class CacheQueueCheck:
    def __init__(self, redis_client: redis.Redis, queues: dict, max_pending: int = 1000):
        self.redis = redis_client
        self.queues = queues  # {"trade_queue": "trade:queue", "data_queue": "data:queue"}
        self.max_pending = max_pending

    def check(self) -> CheckResult:
        overflow_queues = []
        for name, queue_key in self.queues.items():
            pending = self.redis.llen(queue_key)
            if pending > self.max_pending:
                overflow_queues.append(f"{name}: {pending} pending")
            # 检查消费速率，如果积压在增长，即使未超阈值也要关注
            elif pending > self.max_pending * 0.7:
                overflow_queues.append(f"{name}: {pending} pending (near limit)")

        if not overflow_queues:
            return CheckResult("cache_queue", HealthStatus.HEALTHY, "queues normal")
        return CheckResult("cache_queue", HealthStatus.WARNING, "; ".join(overflow_queues))

磁盘空间检查

import shutil

class DiskSpaceCheck:
    def __init__(self, paths: list, warning_threshold: float = 0.85):
        self.paths = paths
        self.warning_threshold = warning_threshold

    def check(self) -> CheckResult:
        full_paths = []
        for path in self.paths:
            usage = shutil.disk_usage(path)
            percent = usage.used / usage.total
            if percent > self.warning_threshold:
                full_paths.append(f"{path}: {percent:.1%} used")

        if not full_paths:
            return CheckResult("disk_space", HealthStatus.HEALTHY, "disk usage normal")
        return CheckResult("disk_space", HealthStatus.CRITICAL, "; ".join(full_paths))

任务执行记录检查

定时任务可能因为异常退出而静默停止。检查最近一次执行时间，超过周期就告警。

class TaskExecutionCheck:
    def __init__(self, task_store: dict, task_schedules: dict):
        self.store = task_store  # {"task_name": last_execution_timestamp}
        self.schedules = task_schedules  # {"task_name": interval_seconds}

    def check(self) -> CheckResult:
        missing_tasks = []
        for task_name, interval in self.schedules.items():
            last_run = self.store.get(task_name)
            if last_run is None:
                missing_tasks.append(f"{task_name}: never executed")
                continue
            elapsed = time.time() - last_run
            if elapsed > interval * 2:  # 超过2倍周期视为异常
                missing_tasks.append(f"{task_name}: {elapsed:.0f}s since last run")

        if not missing_tasks:
            return CheckResult("task_execution", HealthStatus.HEALTHY, "all tasks running")
        return CheckResult("task_execution", HealthStatus.CRITICAL, "; ".join(missing_tasks))

告警推送

告警推送要分级。WARNING 级别只记录日志，CRITICAL 级别推送即时消息。推送渠道用 Webhook，对接钉钉/企业微信/飞书都方便。

import requests
import logging

class AlertManager:
    def __init__(self, webhook_url: str, alert_cooldown: int = 300):
        self.webhook_url = webhook_url
        self.alert_cooldown = alert_cooldown
        self._last_alert_time = {}
        self.logger = logging.getLogger("alert")

    def send(self, result: CheckResult):
        # 冷却期内不重复推送同一巡检项
        now = time.time()
        last_time = self._last_alert_time.get(result.item, 0)
        if now - last_time < self.alert_cooldown:
            return

        if result.status == HealthStatus.CRITICAL:
            self._push_webhook(result)
            self.logger.error(f"[{result.item}] {result.detail}")
        elif result.status == HealthStatus.WARNING:
            self.logger.warning(f"[{result.item}] {result.detail}")

        self._last_alert_time[result.item] = now

    def _push_webhook(self, result: CheckResult):
        payload = {
            "msgtype": "text",
            "text": {
                "content": f"⚠️ 交易系统告警\n巡检项: {result.item}\n状态: {result.status.value}\n详情: {result.detail}"
            }
        }
        try:
            requests.post(self.webhook_url, json=payload, timeout=3)
        except Exception as e:
            self.logger.error(f"webhook push failed: {e}")

调度与主流程

巡检任务用 asyncio 实现，每30秒跑一轮。每轮巡检各检查项并行执行，避免单项检查耗时阻塞整体。

import asyncio

class InspectionScheduler:
    def __init__(self, interval: int = 30):
        self.interval = interval
        self.checkers = []
        self.alert_manager = AlertManager(webhook_url="https://your-webhook-url")

    def register_checker(self, checker):
        self.checkers.append(checker)

    async def run_once(self):
        results = await asyncio.gather(*[self._run_checker(c) for c in self.checkers])
        for result in results:
            if result.status != HealthStatus.HEALTHY:
                self.alert_manager.send(result)

    async def _run_checker(self, checker):
        try:
            if asyncio.iscoroutinefunction(checker.check):
                return await checker.check()
            return checker.check()
        except Exception as e:
            return CheckResult(checker.__class__.__name__, HealthStatus.CRITICAL, str(e))

    async def start(self):
        while True:
            await self.run_once()
            await asyncio.sleep(self.interval)

集成与部署

主程序启动时初始化调度器并注册各巡检项：

def setup_inspection():
    scheduler = InspectionScheduler(interval=30)

    # 注册各巡检项
    scheduler.register_checker(APIConnectionCheck([
        {"name": "market_api", "url": "http://localhost:8080/ping"}
    ]))

    scheduler.register_checker(DataFreshnessCheck(
        db_conn=your_db_conn,
        symbols=["BTC_USDT", "ETH_USDT"],
        max_delay_seconds=60
    ))

    scheduler.register_checker(CacheQueueCheck(
        redis_client=your_redis,
        queues={"trade_queue": "trade:queue", "data_queue": "data:queue"},
        max_pending=1000
    ))

    scheduler.register_checker(DiskSpaceCheck([
        "/var/log/trading",
        "/data/market_data"
    ]))

    scheduler.register_checker(TaskExecutionCheck(
        task_store=your_task_store,
        task_schedules={
            "fetch_kline": 60,
            "sync_order_status": 30
        }

    return scheduler

部署时用 supervisor 或 systemd 守护进程，确保巡检模块本身不挂。巡检模块的日志单独输出到独立文件，方便排查。

实际运行中的几个注意点

巡检模块自身不能成为单点。如果巡检进程挂了，系统就失去监控。用 watchdog 或外部监控（如云监控）做进程守护。

告警要设冷却期。网络抖动可能导致多个巡检项同时告警，冷却期避免告警风暴。上面代码里 alert_cooldown 参数控制了同一巡检项的告警频率。

巡检项要可配置。不同交易系统的关键路径不同，把巡检项做成配置驱动，上线新策略时只需改配置，不用改代码。

巡检结果要持久化。记录历史巡检数据，便于事后分析系统稳定性。可以存到 SQLite 或时序数据库，按天归档。

巡检模块的价值在于把"系统是否正常"这个问题从主观判断变成客观指标。每次告警都是一次系统问题的提前暴露，省去的是半夜爬起来看日志的时间。
