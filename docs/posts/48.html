Python日志系统设计：分级输出与文件轮转

2026-10-18 系统运维

日志是长期运行程序的基础设施。量化交易系统、爬虫、定时任务，只要程序跑起来超过几分钟，就必须有一套可靠的日志方案。print 只能救急，logging 才是正解。这篇文章拆解一套可直接落地的日志系统设计：分级输出、文件轮转、格式规范、异常捕获，以及长期运行程序的日志管理策略。

一、为什么不用 print

先说清楚问题。print 的缺陷：

  • 无法分级，DEBUG 信息和 ERROR 信息混在一起
  • 无法按级别过滤，生产环境想关掉调试输出得改代码
  • 没有时间戳、模块名、行号，排查问题时定位困难
  • 不支持输出到多个目标（控制台 + 文件 + 远程）
  • 文件会无限增长，没有轮转机制

logging 模块解决以上全部问题。标准库自带，无需安装。

二、日志分级：五个级别的实际用法

Python logging 定义了五个标准级别，数值越大越严重：

级别 数值 使用场景
DEBUG 10 变量值、函数入参、循环中间状态
INFO 20 程序启动、任务完成、关键流程节点
WARNING 30 可恢复的异常、降级处理、配置缺失
ERROR 40 功能失败，但程序还能继续跑
CRITICAL 50 程序无法继续，需要立即人工介入

关键规则：logger 的有效级别 = 自身级别与所有 handler 级别中最严格的那个。很多人配置了 logger.setLevel(logging.DEBUG) 但发现 DEBUG 日志不输出，原因往往是 handler 的级别还停留在默认的 WARNING。

一个常见的误区是把所有信息都打成 INFO。实际项目中，INFO 应该只保留"业务上有意义的事件"，比如"策略信号触发""订单提交成功"。循环里的每次迭代、每个中间变量，一律 DEBUG。这样生产环境把级别调到 INFO，日志量立刻降下来。

三、基础配置：从 logging.basicConfig 到完整方案

basicConfig 适合脚本快速上手：

import logging

logging.basicConfig(
    level=logging.INFO,
    format="%(asctime)s | %(levelname)-8s | %(name)s | %(message)s",
    datefmt="%Y-%m-%d %H:%M:%S",
)
logger = logging.getLogger(__name__)
logger.info("程序启动")

但它只能配置一次，且无法同时输出到控制台和文件（不同格式）。生产环境建议用 dictConfig 或手动构建 handler。下面直接给一套完整方案。

四、完整日志系统实现

4.1 日志格式设计

格式字段的选择直接影响排查效率。推荐包含：时间戳（精确到毫秒）、级别、模块名、行号、消息。

LOG_FORMAT = (
    "%(asctime)s.%(msecs)03d | %(levelname)-8s | "
    "%(name)s:%(lineno)d | %(message)s"
)
DATE_FORMAT = "%Y-%m-%d %H:%M:%S"

%(name)s 是 logger 名称，通常用 __name__ 传入，能看出日志来自哪个模块。%(lineno)d 是行号，排查时直接跳转。%(msecs)03d 补三位毫秒，高频交易场景下秒级时间戳不够用。

4.2 按大小轮转：RotatingFileHandler

最常用的轮转策略。单个文件达到上限就切分，保留 N 个备份。

import logging
from logging.handlers import RotatingFileHandler
import os

def build_logger(
    name: str,
    log_dir: str = "logs",
    level: int = logging.INFO,
    max_bytes: int = 10 * 1024 * 1024,  # 10MB
    backup_count: int = 5,
) -> logging.Logger:
    os.makedirs(log_dir, exist_ok=True)

    logger = logging.getLogger(name)
    logger.setLevel(logging.DEBUG)  # logger 本身放开，由 handler 控制
    logger.propagate = False

    # 避免重复添加 handler（模块被多次 import 时）
    if logger.handlers:
        return logger

    formatter = logging.Formatter(LOG_FORMAT, DATE_FORMAT)

    # 控制台：只输出 INFO 及以上
    console = logging.StreamHandler()
    console.setLevel(logging.INFO)
    console.setFormatter(formatter)

    # 文件：记录 DEBUG 及以上，按大小轮转
    file_handler = RotatingFileHandler(
        os.path.join(log_dir, f"{name}.log"),
        maxBytes=max_bytes,
        backupCount=backup_count,
        encoding="utf-8",
    )
    file_handler.setLevel(logging.DEBUG)
    file_handler.setFormatter(formatter)

    logger.addHandler(console)
    logger.addHandler(file_handler)
    return logger


if __name__ == "__main__":
    log = build_logger("demo")
    log.debug("这条只进文件")
    log.info("这条同时进控制台和文件")
    log.error("错误信息")

这样配置后，控制台保持干净（只看 INFO 以上），文件里保留完整的 DEBUG 链路，出问题时可以回溯。

4.3 按时间轮转：TimedRotatingFileHandler

适合日志量不稳定、但需要按天/小时归档的场景。量化系统经常需要"按交易日切分日志"，这个 handler 更合适。

from logging.handlers import TimedRotatingFileHandler

def add_timed_handler(logger: logging.Logger, log_dir: str = "logs") -> None:
    os.makedirs(log_dir, exist_ok=True)
    formatter = logging.Formatter(LOG_FORMAT, DATE_FORMAT)

    handler = TimedRotatingFileHandler(
        os.path.join(log_dir, "app.log"),
        when="midnight",      # 每天零点切分
        interval=1,
        backupCount=30,       # 保留 30 天
        encoding="utf-8",
        utc=False,            # 用本地时间
    )
    handler.suffix = "%Y-%m-%d"   # 切分后的文件名后缀
    handler.setLevel(logging.DEBUG)
    handler.setFormatter(formatter)
    logger.addHandler(handler)

when 参数支持 S（秒）、M（分）、H（小时）、D（天）、midnight（每天零点）、W0~W6（每周几）。注意 backupCount 在 midnight 模式下表示保留的天数。

两种轮转的取舍：按大小轮转能控制磁盘占用上限，但切分时间点不可预测；按时间轮转便于归档和检索，但单日日志量可能爆炸。实际项目里可以两个 handler 同时挂载——一个按大小兜底，一个按天归档。

4.4 异常自动记录

这是最容易被忽略的部分。logger.error(str(e)) 只记录异常消息，丢掉 traceback，等于白记。正确做法：

import traceback

# 方式一：在 except 块中
try:
    1 / 0
except Exception:
    log.exception("计算任务失败")   # 自动带上完整 traceback

# 方式二：手动格式化
try:
    raise ValueError("bad config")
except Exception as e:
    log.error("配置解析失败: %s\n%s", e, traceback.format_exc())

logger.exception() 等价于 logger.error(..., exc_info=True)，必须在 except 块内调用才有效。

对于长期运行的服务，建议在入口处统一捕获未处理异常：

import sys

def main():
    log = build_logger("app")
    try:
        run_service()
    except KeyboardInterrupt:
        log.info("收到中断信号，准备退出")
    except Exception:
        log.exception("未捕获异常，程序退出")
        sys.exit(1)

另外，可以用 sys.excepthook 兜底那些逃逸出 try 的异常：

def install_excepthook(logger: logging.Logger) -> None:
    def handler(exc_type, exc_value, exc_tb):
        if issubclass(exc_type, KeyboardInterrupt):
            sys.__excepthook__(exc_type, exc_value, exc_tb)
            return
        logger.critical("未捕获异常", exc_info=(exc_type, exc_value, exc_tb))
    sys.excepthook = handler

五、长期运行程序的日志管理

5.1 用 dictConfig 统一配置

当项目模块变多，手动 addHandler 会变得散乱。logging.config.dictConfig 支持用字典集中声明，还能读取 YAML/JSON 配置。

import logging.config

LOGGING_CONFIG = {
    "version": 1,
    "disable_existing_loggers": False,
    "formatters": {
        "standard": {
            "format": LOG_FORMAT,
            "datefmt": DATE_FORMAT,
        },
    },
    "handlers": {
        "console": {
            "class": "logging.StreamHandler",
            "level": "INFO",
            "formatter": "standard",
            "stream": "ext://sys.stdout",
        },
        "file": {
            "class": "logging.handlers.RotatingFileHandler",
            "level": "DEBUG",
            "formatter": "standard",
            "filename": "logs/app.log",
            "maxBytes": 10485760,
            "backupCount": 5,
            "encoding": "utf-8",
        },
    },
    "loggers": {
        "app": {
            "level": "DEBUG",
            "handlers": ["console", "file"],
            "propagate": False,
        },
    },
    "root": {
        "level": "WARNING",
        "handlers": ["console"],
    },
}

logging.config.dictConfig(LOGGING_CONFIG)
log = logging.getLogger("app")

disable_existing_loggers: False 很重要——默认值是 True，会把已经创建的 logger 全部禁用，第三方库的日志也跟着消失。

5.2 多进程场景的坑

RotatingFileHandler 在多进程下不安全：多个进程同时写同一个文件、同时触发轮转，会导致日志丢失或文件损坏。解决方案：

  • 每个进程写独立文件：文件名带上 PID 或 worker 编号
  • 用 QueueHandler + QueueListener：主进程统一写盘，子进程只往队列里丢
from logging.handlers import QueueHandler, QueueListener
import multiprocessing as mp
import queue

def worker_process(log_queue: mp.Queue, worker_id: int):
    logger = logging.getLogger(f"worker-{worker_id}")
    logger.setLevel(logging.DEBUG)
    logger.addHandler(QueueHandler(log_queue))
    logger.info("worker %d 启动", worker_id)
    # ... 业务逻辑

def run_with_queue():
    log_queue = mp.Queue()
    logger = build_logger("main")
    listener = QueueListener(log_queue, *logger.handlers)
    listener.start()
    try:
        procs = [
            mp.Process(target=worker_process, args=(log_queue, i))
            for i in range(4)
        ]
        for p in procs:
            p.start()
        for p in procs:
            p.join()
    finally:
        listener.stop()

队列方案把写盘集中到单点，彻底规避竞争。

5.3 日志量与磁盘控制

长期运行的程序要算一笔账：假设每秒 100 条日志，平均每行 200 字节，一天就是 1.7GB。几个控制手段：

  1. 生产环境把级别调到 INFO 或 WARNING，DEBUG 只在排障时临时开启
  2. backupCount 必须设置，否则旧日志永远不删
  3. 高频日志用采样：循环里的日志加计数器，每 N 次打一条
  4. 日志目录单独挂载，避免写满系统盘导致服务崩溃
class SampledLogger:
    """每 N 次调用才真正输出一次，用于高频循环"""
    def __init__(self, logger: logging.Logger, every: int = 100):
        self.logger = logger
        self.every = every
        self.count = 0

    def debug(self, msg, *args):
        self.count += 1
        if self.count % self.every == 0:
            self.logger.debug("[sampled %d] " + msg, self.count, *args)

5.4 日志中不要记录敏感信息

账户信息、API key、完整订单参数，写进日志就是安全隐患。建议在格式化阶段做脱敏，或者约定"敏感字段用 *** 占位"。这一点在量化系统里尤其重要——日志文件经常被复制、上传、共享。

六、小结

一套可用的日志系统，核心就四件事：

  • 分级：logger 放开到 DEBUG，handler 按目标控制级别，控制台只看 INFO 以上
  • 轮转：按大小兜底磁盘，按时间便于归档，两者可叠加
  • 格式：时间戳到毫秒、级别、模块名、行号，一个都不能少
  • 异常：用 logger.exception() 保留 traceback，入口处兜底 excepthook

多进程用队列，长期运行控磁盘，敏感信息做脱敏。把这几点做到位，排查线上问题时就不会对着空日志干瞪眼。
