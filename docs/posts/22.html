信号扫描模块设计与实现：多指标并行检测

2026-09-03 Python自动化

行情数据每时每刻都在变动，人工盯盘去验证指标条件，既低效又容易遗漏。信号扫描模块的价值在于，将“指标计算”和“条件判定”从人工观察中剥离出来，交给程序去循环执行。本文讨论的是一个通用扫描框架，它负责对多个标的（股票、期货、加密货币等）计算技术指标，并在指标满足预设规则时输出信号。

先明确模块的输入输出： - 输入：一组标的的K线数据（OHLCV），以及一组信号规则。 - 输出：格式化的信号记录，包含标的代码、信号类型、触发时间、当时的价格及指标值。

扫描流程设计

整个扫描流程分为四个阶段，形成一个闭环：

  1. 数据准备：获取或更新K线数据，统一格式。
  2. 指标计算：对每个标的计算所需的全部技术指标。
  3. 规则判定：将最新计算出的指标值与预设规则进行比对，判断是否触发信号。
  4. 信号输出：将触发的信号写入日志、数据库或消息队列。

这里有一个关键设计决策：指标计算与规则判定分离。指标计算是纯函数式的，输入K线，输出指标序列；规则判定则负责逻辑组合。这样做的好处是，新增一个指标不需要改动判定逻辑，反之亦然。

指标计算逻辑

我们使用 pandas 和 numpy 进行向量化计算，避免使用循环。为了保证代码可复用，将指标计算封装在一个独立的类中。

import pandas as pd
import numpy as np

class TechnicalIndicators:
    """技术指标计算器，使用向量化计算提升性能"""

    @staticmethod
    def SMA(series: pd.Series, period: int) -> pd.Series:
        """简单移动平均线"""
        return series.rolling(window=period).mean()

    @staticmethod
    def EMA(series: pd.Series, period: int) -> pd.Series:
        """指数移动平均线"""
        return series.ewm(span=period, adjust=False).mean()

    @staticmethod
    def RSI(series: pd.Series, period: int = 14) -> pd.Series:
        """相对强弱指数 (RSI)"""
        delta = series.diff()
        gain = delta.clip(lower=0)
        loss = -delta.clip(upper=0)
        avg_gain = gain.ewm(alpha=1/period, min_periods=period).mean()
        avg_loss = loss.ewm(alpha=1/period, min_periods=period).mean()
        rs = avg_gain / avg_loss
        rsi = 100 - (100 / (1 + rs))
        return rsi

    @staticmethod
    def MACD(series: pd.Series, fast: int = 12, slow: int = 26, signal: int = 9):
        """MACD指标，返回 (DIF, DEA, HIST)"""
        ema_fast = TechnicalIndicators.EMA(series, fast)
        ema_slow = TechnicalIndicators.EMA(series, slow)
        dif = ema_fast - ema_slow
        dea = TechnicalIndicators.EMA(dif, signal)
        hist = (dif - dea) * 2
        return dif, dea, hist

    @staticmethod
    def BOLL(series: pd.Series, period: int = 20, num_std: float = 2.0):
        """布林带，返回 (上轨, 中轨, 下轨)"""
        middle = TechnicalIndicators.SMA(series, period)
        std = series.rolling(window=period).std()
        upper = middle + (std * num_std)
        lower = middle - (std * num_std)
        return upper, middle, lower

信号规则定义

规则定义是整个模块的灵魂。我们采用声明式的规则结构，用字典描述条件，而不是硬编码 if-else。这样，调整策略只需要修改配置文件，不需要动代码。

规则结构设计如下：

{
    "name": "均线多头排列",
    "conditions": [
        {"indicator": "SMA", "params": {"period": 5}, "target": "close",
         "operator": ">", "compare_to": {"indicator": "SMA", "params": {"period": 20}, "target": "close"}},
        {"indicator": "SMA", "params": {"period": 20}, "target": "close",
         "operator": ">", "compare_to": {"indicator": "SMA", "params": {"period": 60}, "target": "close"}}
    ],
    "logic": "AND"  # 所有条件同时满足才触发
}

判定引擎负责解析这个规则字典。它从指标缓存中取出对应的指标序列，取最后一个值（最新值）进行比较。

信号判定引擎

import importlib
from typing import Dict, List, Any

class SignalEngine:
    """信号判定引擎，解析规则并执行比较"""

    def __init__(self, data: pd.DataFrame):
        """
        :param data: 包含OHLCV的DataFrame，索引为时间
        """
        self.data = data
        self._indicator_cache: Dict[str, pd.Series] = {}

    def _compute_indicator(self, indicator_name: str, params: Dict, target: str):
        """计算指标并缓存结果，避免重复计算"""
        cache_key = f"{indicator_name}_{target}_{str(params)}"
        if cache_key in self._indicator_cache:
            return self._indicator_cache[cache_key]

        indicator_func = getattr(TechnicalIndicators, indicator_name)
        series = self.data[target]

        # 处理返回多个值的情况（如MACD、BOLL）
        result = indicator_func(series, **params)
        if isinstance(result, tuple):
            # 对于多返回值指标，需要指定取第几个，这里简化处理
            # 实际应用中可通过 params 中的 'output_index' 指定
            result = result[0]

        self._indicator_cache[cache_key] = result
        return result

    def _get_value(self, spec: Dict) -> float:
        """根据规格获取指标的最新值或指定值"""
        if 'indicator' in spec:
            series = self._compute_indicator(spec['indicator'], spec.get('params', {}), spec['target'])
            return series.iloc[-1]  # 取最新值
        elif 'value' in spec:
            return float(spec['value'])
        else:
            raise ValueError(f"无法解析的规格: {spec}")

    def check_rule(self, rule: Dict) -> bool:
        """检查单条规则是否触发"""
        conditions = rule['conditions']
        logic = rule.get('logic', 'AND')

        results = []
        for cond in conditions:
            left_val = self._get_value(cond)
            right_spec = cond.get('compare_to')
            if right_spec:
                right_val = self._get_value(right_spec)
            else:
                right_val = cond.get('threshold')  # 直接阈值比较

            operator = cond['operator']
            if operator == '>':
                results.append(left_val > right_val)
            elif operator == '<':
                results.append(left_val < right_val)
            elif operator == '>=':
                results.append(left_val >= right_val)
            elif operator == '<=':
                results.append(left_val <= right_val)
            elif operator == '==':
                results.append(abs(left_val - right_val) < 1e-8)  # 浮点数比较
            elif operator == 'cross_above':
                # 上穿：前一个值小于等于，当前值大于
                series_left = self._compute_indicator(cond['indicator'], cond.get('params', {}), cond['target'])
                series_right = self._compute_indicator(right_spec['indicator'], right_spec.get('params', {}), right_spec['target'])
                results.append(series_left.iloc[-2] <= series_right.iloc[-2] and series_left.iloc[-1] > series_right.iloc[-1])
            elif operator == 'cross_below':
                series_left = self._compute_indicator(cond['indicator'], cond.get('params', {}), cond['target'])
                series_right = self._compute_indicator(right_spec['indicator'], right_spec.get('params', {}), right_spec['target'])
                results.append(series_left.iloc[-2] >= series_right.iloc[-2] and series_left.iloc[-1] < series_right.iloc[-1])
            else:
                raise ValueError(f"未知操作符: {operator}")

        if logic == 'AND':
            return all(results)
        elif logic == 'OR':
            return any(results)
        else:
            raise ValueError(f"未知逻辑: {logic}")

并行扫描控制

单线程循环扫描几百个标的，速度瓶颈不在CPU而在I/O。但如果标的数量上千，指标计算本身也会成为瓶颈。此时使用 concurrent.futures 进行进程级并行是合适的。

from concurrent.futures import ProcessPoolExecutor, as_completed
from typing import List, Dict
import logging

logging.basicConfig(level=logging.INFO, format='%(asctime)s - %(levelname)s - %(message)s')

class ParallelScanner:
    """并行扫描控制器"""

    def __init__(self, rules: List[Dict], max_workers: int = 4):
        self.rules = rules
        self.max_workers = max_workers

    def _scan_single_symbol(self, symbol: str, kline_data: pd.DataFrame) -> List[Dict]:
        """扫描单个标的，返回信号列表"""
        signals = []
        engine = SignalEngine(kline_data)

        for rule in self.rules:
            try:
                if engine.check_rule(rule):
                    signal = {
                        'symbol': symbol,
                        'rule_name': rule['name'],
                        'time': kline_data.index[-1],
                        'close': kline_data['close'].iloc[-1]
                    }
                    signals.append(signal)
            except Exception as e:
                logging.warning(f"标的 {symbol} 检查规则 {rule['name']} 时出错: {e}")
                continue

        return signals

    def scan_all(self, data_map: Dict[str, pd.DataFrame]) -> List[Dict]:
        """
        并行扫描所有标的
        :param data_map: 键为标的代码，值为K线DataFrame
        """
        all_signals = []
        with ProcessPoolExecutor(max_workers=self.max_workers) as executor:
            future_to_symbol = {
                executor.submit(self._scan_single_symbol, symbol, data): symbol
                for symbol, data in data_map.items()
            }

            for future in as_completed(future_to_symbol):
                symbol = future_to_symbol[future]
                try:
                    signals = future.result()
                    all_signals.extend(signals)
                    if signals:
                        logging.info(f"标的 {symbol} 触发了 {len(signals)} 个信号")
                except Exception as e:
                    logging.error(f"扫描标的 {symbol} 时发生异常: {e}")

        return all_signals

完整调用示例

import pandas as pd
from datetime import datetime, timedelta

def generate_demo_data(symbol: str, base_price: float, trend: float = 0.001, volatility: float = 0.02):
    """生成模拟K线数据用于演示"""
    dates = pd.date_range(end=datetime.now(), periods=200, freq='1h')
    np.random.seed(hash(symbol) % 1000)  # 不同标的生成不同序列

    returns = np.random.normal(trend, volatility, len(dates))
    price = base_price * np.exp(np.cumsum(returns))
    df = pd.DataFrame({
        'open': price * (1 + np.random.normal(0, 0.005, len(dates))),
        'high': price * (1 + abs(np.random.normal(0, 0.01, len(dates)))),
        'low': price * (1 - abs(np.random.normal(0, 0.01, len(dates)))),
        'close': price,
        'volume': np.random.randint(1000, 10000, len(dates))
    }, index=dates)
    return df

if __name__ == "__main__":
    # 准备数据：模拟3个标的
    symbols = ["BTC_USDT", "ETH_USDT", "SOL_USDT"]
    data_map = {
        "BTC_USDT": generate_demo_data("BTC_USDT", 50000),
        "ETH_USDT": generate_demo_data("ETH_USDT", 3000),
        "SOL_USDT": generate_demo_data("SOL_USDT", 150)
    }

    # 定义规则集
    rules = [
        {
            "name": "RSI超卖反弹",
            "conditions": [
                {"indicator": "RSI", "params": {"period": 14}, "target": "close",
                 "operator": "<", "threshold": 30}
            ],
            "logic": "AND"
        },
        {
            "name": "MACD金叉",
            "conditions": [
                {"indicator": "MACD", "params": {"fast": 12, "slow": 26, "signal": 9},
                 "target": "close", "operator": "cross_above",
                 "compare_to": {"indicator": "MACD", "params": {"fast": 12, "slow": 26, "signal": 9},
                                "target": "close"}}
            ],
            "logic": "AND"
        },
        {
            "name": "均线多头排列",
            "conditions": [
                {"indicator": "SMA", "params": {"period": 5}, "target": "close",
                 "operator": ">", "compare_to": {"indicator": "SMA", "params": {"period": 20}, "target": "close"}},
                {"indicator": "SMA", "params": {"period": 20}, "target": "close",
                 "operator": ">", "compare_to": {"indicator": "SMA", "params": {"period": 60}, "target": "close"}}
            ],
            "logic": "AND"
        }
    ]

    # 执行扫描
    scanner = ParallelScanner(rules, max_workers=2)
    signals = scanner.scan_all(data_map)

    # 输出结果
    print("\n===== 扫描结果 =====")
    for sig in signals:
        print(f"[{sig['time']}] {sig['symbol']} - {sig['rule_name']} @ {sig['close']:.2f}")

    if not signals:
        print("本次扫描未触发任何信号")

性能优化与注意事项

1. 指标缓存策略 SignalEngine 内部维护了指标缓存。当多个规则都使用 SMA(20) 时，只需计算一次。但要注意，缓存是针对单个标的的，扫描完一个标的后，SignalEngine 实例会被丢弃，不会造成内存泄漏。

2. 数据对齐问题 并行计算时，不同标的的K线长度可能不一致。确保传入的 DataFrame 已经按时间排序，且没有缺失值。建议在数据准备阶段做统一清洗。

3. 规则设计陷阱 定义 cross_above 这类穿越条件时，需要前一根K线的数据。如果数据长度不足（比如刚上市的新标的），iloc[-2] 会抛异常。在 _scan_single_symbol 中已经用 try-except 捕获了异常，但更好的做法是在规则定义时声明 min_bars 要求。

4. 进程池与内存 ProcessPoolExecutor 会将数据序列化后传给子进程。如果 data_map 很大，序列化开销可能超过并行计算带来的收益。对于中小规模数据（几百个标的），可以考虑使用 ThreadPoolExecutor，因为 pandas 的底层计算会释放GIL，线程也能获得加速效果。

扩展方向

这个模块的核心在于规则引擎的灵活性。你可以通过扩展 TechnicalIndicators 类来加入更多指标，比如ATR、CCI、KDJ等。也可以修改 SignalEngine 的 _get_value 方法，让它支持从外部数据源（如基本面数据）取值，实现多维度信号扫描。

此外，输出端可以对接数据库或消息队列，将信号实时推送出去。扫描频率可以设定为定时任务，也可以对接WebSocket实时数据流，实现Tick级别的信号监控。
