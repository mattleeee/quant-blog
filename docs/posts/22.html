信号扫描模块设计与实现：多指标并行检测

2026-09-21 Python自动化

做量化交易系统,信号扫描是最基础也最容易被低估的一环。很多人一开始写个 for 循环遍历标的、逐个算指标、再 if 判断,标的少的时候没问题,一旦标的数量上到几百上千,单线程扫描动辄几十秒,盘中根本来不及。

这篇文章讲清楚一件事:怎么设计一个结构清晰、可扩展、能并行跑的信号扫描模块。只讲技术实现,不涉及任何具体交易品种。

一、扫描流程设计

先把整个流程拆开。一个完整的信号扫描,本质上分四步:

  1. 数据准备:拉取每个标的的历史K线(DataFrame)
  2. 指标计算:对每个标的计算所需技术指标(MA、RSI、MACD 等)
  3. 信号判定:根据指标值判断是否触发信号
  4. 结果汇总:收集触发的信号,统一输出

关键设计点在于:指标计算和信号判定是"每个标的独立"的。标的 A 的计算不依赖标的 B,这正是并行的天然切分点。

所以整体架构是这样的:

标的列表 → [并行池] → 每个worker: 取数据 → 算指标 → 判信号 → 返回结果
                                                              ↓
                                                        汇总过滤输出

用 concurrent.futures 的 ThreadPoolExecutor 还是 ProcessPoolExecutor?

  • 如果指标计算是纯 pandas/numpy 向量化运算,大部分时间在 C 层,会释放 GIL,线程池就够用,而且开销小、数据传递方便。
  • 如果中间有大量 Python 层循环(比如逐行算自定义指标),用进程池更划算,但要考虑数据序列化成本。

实战中我一般默认用线程池,先跑起来,遇到 CPU 瓶颈再换进程池。

二、指标计算逻辑

指标计算不用自己造轮子,但有几个坑要避开。这里给出三个最常用的指标,用 pandas 向量化实现。

import pandas as pd
import numpy as np


def calc_ma(df: pd.DataFrame, periods=(5, 10, 20)) -> pd.DataFrame:
    """计算多条均线"""
    for p in periods:
        df[f"ma{p}"] = df["close"].rolling(window=p).mean()
    return df


def calc_rsi(df: pd.DataFrame, period: int = 14) -> pd.DataFrame:
    """计算RSI,使用Wilder平滑"""
    delta = df["close"].diff()
    gain = delta.clip(lower=0)
    loss = -delta.clip(upper=0)

    # Wilder平滑等价于 alpha = 1/period 的EMA
    avg_gain = gain.ewm(alpha=1 / period, adjust=False).mean()
    avg_loss = loss.ewm(alpha=1 / period, adjust=False).mean()

    rs = avg_gain / avg_loss.replace(0, np.nan)
    df[f"rsi{period}"] = 100 - (100 / (1 + rs))
    return df


def calc_macd(df: pd.DataFrame, fast=12, slow=26, signal=9) -> pd.DataFrame:
    """计算MACD"""
    ema_fast = df["close"].ewm(span=fast, adjust=False).mean()
    ema_slow = df["close"].ewm(span=slow, adjust=False).mean()
    df["dif"] = ema_fast - ema_slow
    df["dea"] = df["dif"].ewm(span=signal, adjust=False).mean()
    df["macd"] = (df["dif"] - df["dea"]) * 2
    return df

几个注意点:

  • RSI 用 Wilder 平滑。很多人直接用 rolling().mean(),结果和主流行情软件对不上。Wilder 平滑本质是 alpha = 1/period 的 EMA,用 ewm(alpha=1/period, adjust=False) 才正确。
  • MACD 的 EMA 用 adjust=False。adjust=True 会引入递归权重差异,和通达信、TradingView 的结果对不齐。
  • 除零处理。avg_loss 可能为 0,直接除会得到 inf,用 replace(0, np.nan) 兜底。

把三个指标串起来,封装成一个统一的计算入口:

def compute_indicators(df: pd.DataFrame) -> pd.DataFrame:
    df = df.copy()
    df = calc_ma(df, periods=(5, 10, 20))
    df = calc_rsi(df, period=14)
    df = calc_macd(df)
    return df

三、信号判定规则

指标算完只是"原材料",真正决定扫描结果的是判定规则。规则最好和计算解耦,单独定义,方便后续扩展。

我习惯把每条规则写成一个函数,输入是计算好的 DataFrame,输出是布尔值(最新一根K线是否触发)。

def signal_ma_golden_cross(df: pd.DataFrame) -> bool:
    """MA5上穿MA20"""
    if len(df) < 21:
        return False
    prev, curr = df.iloc[-2], df.iloc[-1]
    return prev["ma5"] <= prev["ma20"] and curr["ma5"] > curr["ma20"]


def signal_rsi_oversold(df: pd.DataFrame) -> bool:
    """RSI从超卖区回升"""
    if len(df) < 2:
        return False
    prev, curr = df.iloc[-2], df.iloc[-1]
    return prev["rsi14"] < 30 and curr["rsi14"] >= 30


def signal_macd_golden_cross(df: pd.DataFrame) -> bool:
    """MACD金叉:DIF上穿DEA"""
    if len(df) < 2:
        return False
    prev, curr = df.iloc[-2], df.iloc[-1]
    return prev["dif"] <= prev["dea"] and curr["dif"] > curr["dea"]

用字典注册规则,方便批量管理:

SIGNAL_RULES = {
    "MA金叉": signal_ma_golden_cross,
    "RSI超卖回升": signal_rsi_oversold,
    "MACD金叉": signal_macd_golden_cross,
}


def check_signals(df: pd.DataFrame) -> list:
    """返回该标的所有触发的信号名"""
    return [name for name, rule in SIGNAL_RULES.items() if rule(df)]

这样设计的好处:加一条新规则,只要写个函数、往字典里塞一行就行,扫描主流程完全不用动。

四、并行扫描实现

现在把前面三块拼起来。核心是 scan_one——处理单个标的的完整流程,然后交给线程池批量执行。

import time
from concurrent.futures import ThreadPoolExecutor, as_completed
from typing import Callable


def scan_one(symbol: str,
             fetch_func: Callable[[str], pd.DataFrame],
             rules: dict) -> dict:
    """扫描单个标的,返回结果字典"""
    try:
        df = fetch_func(symbol)
        if df is None or len(df) < 30:
            return {"symbol": symbol, "signals": [], "error": "数据不足"}

        df = compute_indicators(df)
        signals = [name for name, rule in rules.items() if rule(df)]

        return {
            "symbol": symbol,
            "signals": signals,
            "close": float(df["close"].iloc[-1]),
            "error": None,
        }
    except Exception as e:
        return {"symbol": symbol, "signals": [], "error": str(e)}


def scan_all(symbols: list,
             fetch_func: Callable[[str], pd.DataFrame],
             rules: dict = None,
             max_workers: int = 8) -> list:
    """并行扫描所有标的,只返回有信号的"""
    rules = rules or SIGNAL_RULES
    results = []

    with ThreadPoolExecutor(max_workers=max_workers) as executor:
        futures = {
            executor.submit(scan_one, sym, fetch_func, rules): sym
            for sym in symbols
        }
        for future in as_completed(futures):
            res = future.result()
            if res["signals"]:
                results.append(res)

    return results

几点工程上的考量:

1. max_workers 不要拍脑袋。 如果是网络 IO 密集(每个标的要请求接口拉数据),可以设到 16~32;如果是本地数据、纯计算,设成 CPU 核心数附近即可。给个默认 8 是个稳妥起点。

2. 异常必须吞掉但不能丢。 scan_one 里用 try/except 包住,单个标的失败不能拖垮整个扫描。错误信息塞进返回值,最后统一看。

3. 用 as_completed 而不是 map。 前者谁先完成谁先处理,配合进度条体验更好,也方便做超时控制。

4. 只返回有信号的。 扫描结果动辄几百条,过滤掉空信号能大幅减少后续处理量。

跑一下看看:

def mock_fetch(symbol: str) -> pd.DataFrame:
    """模拟数据源:生成随机K线"""
    n = 100
    np.random.seed(hash(symbol) % 2**32)
    close = 100 + np.cumsum(np.random.randn(n))
    return pd.DataFrame({
        "open": close + np.random.randn(n) * 0.5,
        "high": close + np.abs(np.random.randn(n)),
        "low": close - np.abs(np.random.randn(n)),
        "close": close,
        "volume": np.random.randint(1000, 10000, n),
    })


if __name__ == "__main__":
    symbols = [f"SYM{i:04d}" for i in range(200)]

    t0 = time.time()
    hits = scan_all(symbols, mock_fetch, max_workers=8)
    elapsed = time.time() - t0

    print(f"扫描 {len(symbols)} 个标的,耗时 {elapsed:.2f}s,命中 {len(hits)} 个")
    for h in hits[:5]:
        print(f"  {h['symbol']}: {h['signals']} @ {h['close']:.2f}")

五、性能与扩展

性能优化方向:

  • 指标计算向量化到底。 避免在 scan_one 里出现逐行 for 循环,所有指标用 pandas 内置方法。这一步做对了,单标的耗时通常能压到毫秒级。
  • 数据缓存。 同一批标的在同一天内多次扫描,历史K线不变,可以缓存到本地(parquet 或 pickle),避免重复拉取。
  • 增量计算。 如果只是判断"最新一根K线"的信号,其实只需要最后 N+1 根数据(N 是最长指标周期)。拉全量历史是浪费,取 tail(60) 足矣。

扩展方向:

  • 规则参数化。 把 SIGNAL_RULES 从函数字典升级成配置驱动,比如 {"ma_cross": {"fast": 5, "slow": 20}},方便做参数扫描。
  • 信号打分。 多个信号同时触发时,可以给每个信号一个权重,汇总成分数排序,而不是简单罗列。
  • 接入回测。 扫描模块天然可以复用给回测——把"最新一根"改成"遍历历史每根",就是信号序列生成器。

一个容易忽略的点:时间对齐。 并行扫描时,如果数据源是实时接口,不同标的返回的最后一根K线时间戳可能不一致。做信号判定前,最好统一对齐到某个时间点,否则会出现"用不同时刻的数据做同一批判断"的问题。

小结

信号扫描模块的设计核心就三条:

  1. 计算与判定解耦——指标归指标,规则归规则,各自独立可测。
  2. 以标的为最小并行单元——scan_one 处理单标的,scan_all 负责调度。
  3. 异常隔离——单个标的失败不影响整体,错误信息保留。

这套结构不复杂,但足够撑起几百到几千标的的日常扫描。真正的功夫在细节:指标算法要准、除零要防、并发数要调、数据要缓存。把这些做到位,扫描模块就是整个量化系统里最稳的一块基石。
