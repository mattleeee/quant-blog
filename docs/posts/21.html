模拟交易系统架构设计：从信号扫描到自动执行

2026-08-30 Python自动化

模拟交易系统是量化策略从研究走向实盘的关键桥梁。它不仅要验证策略逻辑的可行性，还要暴露延迟、滑点、数据源稳定性等实战问题。本文分享一套完整的模拟交易系统架构，覆盖信号扫描、市场分析、模拟撮合与通知推送四大模块，并给出可直接参考的 Python 代码骨架。

一、整体架构与数据流向

系统采用 事件驱动 + 异步任务 架构，模块间通过消息队列解耦，避免单点阻塞。核心数据流如下：

数据源(行情/财务) -> 信号扫描模块 -> 候选信号队列 -> 市场分析模块 -> 有效信号队列 -> 模拟交易引擎 -> 持仓/订单状态 -> 推送通知模块

各模块职责划分：

模块 职责 关键技术
信号扫描模块 定时拉取行情数据，计算技术指标，识别潜在交易信号 APScheduler, Pandas
市场分析模块 对候选信号做多维度过滤（流动性、波动率、相关性） NumPy, Scipy
模拟交易引擎 维护虚拟账户，模拟订单撮合、手续费、滑点 asyncio, 状态机
推送通知模块 将信号、成交、异常推送到钉钉/Telegram/邮件 aiohttp, smtplib

二、信号扫描模块：定时任务与数据管道

信号扫描模块是整个系统的“眼睛”。它负责周期性地抓取行情数据，计算指标，并判断是否触发策略条件。为了避免阻塞事件循环，使用 asyncio 配合 APScheduler 实现异步定时扫描。

import asyncio
import aiohttp
import pandas as pd
from apscheduler.schedulers.asyncio import AsyncIOScheduler
from datetime import datetime

class SignalScanner:
    def __init__(self, data_source, strategy_func):
        self.data_source = data_source
        self.strategy = strategy_func
        self.scheduler = AsyncIOScheduler()

    async def fetch_data(self, symbol: str) -> pd.DataFrame:
        """异步获取K线数据"""
        url = f"https://api.example.com/klines?symbol={symbol}&interval=5m"
        async with aiohttp.ClientSession() as session:
            async with session.get(url) as resp:
                data = await resp.json()
                df = pd.DataFrame(data)
                df['timestamp'] = pd.to_datetime(df['timestamp'], unit='ms')
                return df.set_index('timestamp')

    async def scan_single(self, symbol: str):
        """扫描单品种并发布信号"""
        try:
            df = await self.fetch_data(symbol)
            signal = self.strategy(df)  # 返回信号类型: 'BUY', 'SELL', None
            if signal:
                # 发布到消息队列
                await self.publish_signal({
                    'symbol': symbol,
                    'signal': signal,
                    'price': df['close'].iloc[-1],
                    'timestamp': datetime.now().isoformat()
                })
        except Exception as e:
            logging.error(f"Scan {symbol} failed: {e}")

    async def run_forever(self):
        """启动定时扫描任务"""
        symbols = ["BTCUSDT", "ETHUSDT", "SOLUSDT"]
        for sym in symbols:
            self.scheduler.add_job(
                self.scan_single, 
                'interval', 
                minutes=5,
                args=[sym]
            )
        self.scheduler.start()

        # 保持任务运行
        while True:
            await asyncio.sleep(1)

设计要点： - 数据源接口抽象，便于切换真盘/模拟数据 - 策略函数独立，支持热更新 - 信号发布采用异步队列，避免阻塞扫描循环

三、市场分析模块：信号过滤与风险评估

原始信号往往噪声较大。市场分析模块负责对候选信号做二次确认，过滤掉流动性差、波动异常的标的。这里采用 多因子打分制，每个因子输出0-1的得分，最终加权求和，超过阈值才放行。

import numpy as np
from dataclasses import dataclass

@dataclass
class SignalContext:
    symbol: str
    signal: str
    price: float
    volume: float
    volatility: float  # 20周期波动率
    spread: float      # 买卖价差

class MarketAnalyzer:
    def __init__(self, min_score=0.7):
        self.min_score = min_score

    def liquidity_factor(self, ctx: SignalContext) -> float:
        """流动性因子：成交量越大得分越高"""
        # 假设阈值：成交量 > 10000 手为满分
        score = min(ctx.volume / 10000, 1.0)
        return score

    def volatility_factor(self, ctx: SignalContext) -> float:
        """波动率因子：过高过低都降低得分"""
        if 0.02 <= ctx.volatility <= 0.05:
            return 1.0
        elif ctx.volatility < 0.01 or ctx.volatility > 0.08:
            return 0.2
        else:
            return 0.6

    def spread_factor(self, ctx: SignalContext) -> float:
        """价差因子：价差越小越好"""
        return max(0, 1 - ctx.spread / 0.001)

    def analyze(self, ctx: SignalContext) -> bool:
        """综合评分，返回是否通过"""
        weights = {
            'liquidity': 0.4,
            'volatility': 0.3,
            'spread': 0.3
        }
        scores = {
            'liquidity': self.liquidity_factor(ctx),
            'volatility': self.volatility_factor(ctx),
            'spread': self.spread_factor(ctx)
        }
        total = sum(weights[k] * scores[k] for k in weights)
        return total >= self.min_score

设计要点： - 因子函数独立，方便加减因子 - 权重配置化，通过配置文件调整 - 分析结果与原始信号绑定，避免重复计算

四、模拟交易引擎：撮合与资金管理

模拟交易引擎是系统的核心，它必须真实模拟下单、撮合、手续费和滑点。这里采用 事件循环 + 状态机 模式，每个订单有明确的状态流转。

from enum import Enum
from dataclasses import dataclass, field
import asyncio
import uuid

class OrderStatus(Enum):
    PENDING = "PENDING"
    FILLED = "FILLED"
    CANCELLED = "CANCELLED"
    REJECTED = "REJECTED"

@dataclass
class Order:
    order_id: str
    symbol: str
    side: str  # 'BUY' or 'SELL'
    quantity: float
    limit_price: float
    status: OrderStatus = OrderStatus.PENDING
    filled_price: float = None

class SimulatedBroker:
    def __init__(self, initial_cash=100000, fee_rate=0.001, slippage=0.0005):
        self.cash = initial_cash
        self.positions = {}  # symbol -> quantity
        self.orders = {}
        self.fee_rate = fee_rate
        self.slippage = slippage

    async def place_order(self, symbol: str, side: str, qty: float, price: float) -> Order:
        """模拟下单，加入滑点和手续费"""
        # 模拟滑点：买单价格上浮，卖单价格下浮
        if side == 'BUY':
            fill_price = price * (1 + self.slippage)
        else:
            fill_price = price * (1 - self.slippage)

        # 计算手续费
        fee = qty * fill_price * self.fee_rate

        # 检查资金/持仓是否充足
        if side == 'BUY':
            total_cost = qty * fill_price + fee
            if total_cost > self.cash:
                return Order(
                    order_id=str(uuid.uuid4()), 
                    symbol=symbol, side=side, 
                    quantity=qty, limit_price=price,
                    status=OrderStatus.REJECTED
                )
        else:
            if self.positions.get(symbol, 0) < qty:
                return Order(
                    order_id=str(uuid.uuid4()), 
                    symbol=symbol, side=side, 
                    quantity=qty, limit_price=price,
                    status=OrderStatus.REJECTED
                )

        # 模拟成交
        order = Order(
            order_id=str(uuid.uuid4()),
            symbol=symbol, side=side,
            quantity=qty, limit_price=price,
            status=OrderStatus.FILLED,
            filled_price=fill_price
        )

        # 更新账户
        if side == 'BUY':
            self.cash -= (qty * fill_price + fee)
            self.positions[symbol] = self.positions.get(symbol, 0) + qty
        else:
            self.cash += (qty * fill_price - fee)
            self.positions[symbol] = self.positions.get(symbol, 0) - qty

        self.orders[order.order_id] = order
        return order

    def get_portfolio_value(self, current_prices: dict) -> float:
        """计算总资产 = 现金 + 持仓市值"""
        total = self.cash
        for symbol, qty in self.positions.items():
            total += qty * current_prices[symbol]
        return total

设计要点： - 滑点和手续费参数化，可调整模拟精度 - 订单状态机明确，便于对接实盘API - 账户逻辑独立，方便扩展杠杆、做空等特性

五、推送通知模块：异步多渠道分发

当模拟交易引擎产生成交或异常时，需要及时通知使用者。推送模块采用 优先级队列 + 多通道适配器 设计，支持钉钉、Telegram、邮件等渠道。

import asyncio
import aiohttp
import smtplib
from email.mime.text import MIMEText
from typing import List

class NotificationManager:
    def __init__(self):
        self.queue = asyncio.Queue()
        self.channels = []

    def add_channel(self, channel):
        """注册通知渠道"""
        self.channels.append(channel)

    async def send(self, message: str, level: str = "INFO"):
        """异步发送通知"""
        await self.queue.put((level, message))

    async def run(self):
        """消费者：从队列取消息并分发"""
        while True:
            level, msg = await self.queue.get()
            for ch in self.channels:
                try:
                    await ch.send(level, msg)
                except Exception as e:
                    logging.error(f"Channel {ch.name} failed: {e}")

class DingTalkChannel:
    name = "dingtalk"
    def __init__(self, webhook_url):
        self.webhook_url = webhook_url

    async def send(self, level: str, msg: str):
        """发送到钉钉机器人"""
        payload = {
            "msgtype": "text",
            "text": {"content": f"[{level}] {msg}"}
        }
        async with aiohttp.ClientSession() as session:
            await session.post(self.webhook_url, json=payload)

class EmailChannel:
    name = "email"
    def __init__(self, smtp_host, smtp_port, username, password, to_addr):
        self.smtp_host = smtp_host
        self.smtp_port = smtp_port
        self.username = username
        self.password = password
        self.to_addr = to_addr

    async def send(self, level: str, msg: str):
        """发送到邮件（使用 asyncio.to_thread 避免阻塞）"""
        await asyncio.to_thread(self._send_sync, level, msg)

    def _send_sync(self, level: str, msg: str):
        msg = MIMEText(msg)
        msg['Subject'] = f"[{level}] 模拟交易通知"
        msg['From'] = self.username
        msg['To'] = self.to_addr
        with smtplib.SMTP(self.smtp_host, self.smtp_port) as server:
            server.login(self.username, self.password)
            server.sendmail(self.username, [self.to_addr], msg.as_string())

# 使用示例
notifier = NotificationManager()
notifier.add_channel(DingTalkChannel("https://oapi.dingtalk.com/robot/send?access_token=xxx"))
notifier.add_channel(EmailChannel("smtp.qq.com", 587, "user@qq.com", "pass", "dest@example.com"))
asyncio.create_task(notifier.run())

设计要点： - 消息队列削峰，避免高并发时通知丢失 - 渠道适配器统一接口，新增渠道只需实现 send 方法 - 邮件发送用 to_thread 避免阻塞事件循环

六、系统启动与模块集成

最后，将各模块组装到主程序中。使用 asyncio.gather 并发运行所有模块，确保系统稳定运行。

import asyncio
import logging

logging.basicConfig(level=logging.INFO)

async def main():
    # 初始化各模块
    scanner = SignalScanner(
        data_source="mock", 
        strategy_func=lambda df: "BUY" if df['close'].iloc[-1] > df['ma20'].iloc[-1] else None
    )
    analyzer = MarketAnalyzer(min_score=0.7)
    broker = SimulatedBroker(initial_cash=50000)
    notifier = NotificationManager()

    # 注册通知渠道
    notifier.add_channel(DingTalkChannel("https://oapi.dingtalk.com/robot/send?access_token=xxx"))

    # 启动通知消费者
    notifier_task = asyncio.create_task(notifier.run())

    # 模拟信号处理流程
    async def signal_handler():
        while True:
            signal = await scanner.get_signal()  # 从队列取信号
            ctx = SignalContext(
                symbol=signal['symbol'],
                signal=signal['signal'],
                price=signal['price'],
                volume=10000,  # 从数据源获取
                volatility=0.03,
                spread=0.0002
            )
            if analyzer.analyze(ctx):
                order = await broker.place_order(
                    symbol=ctx.symbol,
                    side=ctx.signal,
                    qty=1,
                    price=ctx.price
                )
                if order.status == OrderStatus.FILLED:
                    await notifier.send(
                        f"成交: {order.symbol} {order.side} {order.quantity} @ {order.filled_price}"
                    )
                else:
                    await notifier.send(
                        f"拒单: {order.symbol} {order.side} 资金/持仓不足",
                        level="WARN"
                    )

    # 并发启动扫描和信号处理
    await asyncio.gather(
        scanner.run_forever(),
        signal_handler(),
        notifier_task
    )

if __name__ == "__main__":
    try:
        asyncio.run(main())
    except KeyboardInterrupt:
        logging.info("System stopped by user")

七、架构优化方向

上述架构已经可以支撑一个基本的模拟交易系统，但在生产环境中还需考虑以下几点：

  1. 数据源容灾：增加多数据源切换机制，主数据源故障时自动降级
  2. 持久化：将订单、持仓、信号记录写入 SQLite/PostgreSQL，便于回测分析
  3. 监控告警：对系统自身指标（延迟、队列积压）做监控，接入 Prometheus
  4. 策略隔离：不同策略跑在不同进程/容器中，避免相互影响
  5. 回测集成：将模拟撮合引擎与历史数据回测打通，统一撮合逻辑

以上是一个完整的模拟交易系统架构设计，各模块代码可直接参考运行。实际使用时，需要根据你的数据源和策略逻辑替换 fetch_data 和 strategy_func 的具体实现。架构的核心思路是 模块解耦、异步驱动、状态可追踪，这套方法论同样适用于实盘交易系统的演进。
