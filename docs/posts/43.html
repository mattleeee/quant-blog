系统重装后的完整恢复流程：从备份到上线

2026-10-12 系统运维

系统重装不是终点，恢复才是。这篇文章记录我最近一次重装 Windows 后的完整恢复流程，涵盖脚本迁移、依赖安装、定时任务重建、历史数据迁移和功能验证。整套流程用 Python 脚本半自动化完成，避免手动操作遗漏。

恢复前的准备：检查清单

重装前如果没做备份，后面全是补救。我的习惯是把关键资产放在一个独立的备份盘里，结构如下：

D:\backup\
├── scripts\           # 所有 Python 脚本
├── data\              # 历史数据（CSV/Parquet/SQLite）
├── configs\           # 配置文件（.env, yaml, json）
├── tasks\             # 定时任务导出（XML）
└── requirements\      # 各项目的依赖清单

重装后先确认这几样东西都在。如果定时任务没提前导出，重装后就只能凭记忆重建——这是最容易踩的坑。

恢复检查清单：

  • [ ] 备份盘可读，目录结构完整
  • [ ] Python 版本与原来一致（建议记录版本号）
  • [ ] 依赖清单存在（pip freeze 导出过）
  • [ ] 定时任务 XML 已导出
  • [ ] 历史数据文件完整（对比文件数量与大小）
  • [ ] 环境变量、API Key 等敏感配置已单独备份

第一步：从备份目录复制脚本

先写一个恢复脚本，把备份目录里的内容按类别分发到目标位置。这样比手动拖拽可靠，也方便重复执行。

import shutil
from pathlib import Path

BACKUP_DIR = Path(r"D:\backup")
TARGET_SCRIPTS = Path(r"D:\scripts")
TARGET_CONFIGS = Path(r"D:\configs")
TARGET_DATA = Path(r"D:\data")

def copy_tree(src: Path, dst: Path, pattern: str = "*"):
    """复制目录内容，保留结构，跳过已存在且大小一致的文件"""
    dst.mkdir(parents=True, exist_ok=True)
    count = 0
    for item in src.rglob(pattern):
        if item.is_file():
            rel = item.relative_to(src)
            target = dst / rel
            target.parent.mkdir(parents=True, exist_ok=True)
            if target.exists() and target.stat().st_size == item.stat().st_size:
                continue
            shutil.copy2(item, target)
            count += 1
    return count

if __name__ == "__main__":
    n1 = copy_tree(BACKUP_DIR / "scripts", TARGET_SCRIPTS, "*.py")
    n2 = copy_tree(BACKUP_DIR / "configs", TARGET_CONFIGS)
    n3 = copy_tree(BACKUP_DIR / "data", TARGET_DATA)
    print(f"scripts: {n1}, configs: {n2}, data: {n3}")

用 copy2 保留时间戳，跳过同名同大小的文件，重复执行不会覆盖新改动。

第二步：安装 Python 依赖

依赖安装最怕版本漂移。我的做法是备份时按项目导出 requirements.txt，恢复时逐个安装。

import subprocess
import sys
from pathlib import Path

REQ_DIR = Path(r"D:\backup\requirements")

def install_requirements(req_file: Path):
    print(f"==> 安装 {req_file.name}")
    result = subprocess.run(
        [sys.executable, "-m", "pip", "install", "-r", str(req_file)],
        capture_output=True, text=True
    )
    if result.returncode != 0:
        print(f"[FAIL] {req_file.name}\n{result.stderr}")
        return False
    print(f"[OK] {req_file.name}")
    return True

if __name__ == "__main__":
    failed = []
    for req in sorted(REQ_DIR.glob("*.txt")):
        if not install_requirements(req):
            failed.append(req.name)
    if failed:
        print("失败的依赖清单：", failed)
    else:
        print("全部依赖安装完成")

几个实践要点：

  1. 先装 pip 自身：python -m pip install --upgrade pip
  2. 国内源加速：加 -i https://pypi.tuna.tsinghua.edu.cn/simple
  3. 虚拟环境隔离：不同项目用不同 venv，别全塞全局环境
  4. 编译型库（如 TA-Lib、pyarrow）可能需先装 Visual C++ Build Tools

如果某个包版本找不到，用 pip install package==x.y.z 精确指定，不要用 >= 让它自由发挥。

第三步：重建 Windows 定时任务

这是重装后最繁琐的一步。Windows 任务计划程序支持用 schtasks 命令行导入 XML，比图形界面点选快得多。

导出与导入

重装前用这条命令导出所有任务：

schtasks /query /fo LIST /v > D:\backup\tasks\all_tasks.txt

更精确的方式是只导出自己创建的任务（排除微软系统任务），然后逐个导出 XML：

import subprocess
from pathlib import Path

EXPORT_DIR = Path(r"D:\backup\tasks")
EXPORT_DIR.mkdir(exist_ok=True)

def export_tasks():
    result = subprocess.run(
        ["schtasks", "/query", "/fo", "CSV", "/nh"],
        capture_output=True, text=True, encoding="gbk"
    )
    for line in result.stdout.splitlines():
        parts = line.split(",")
        if len(parts) < 2:
            continue
        name = parts[0].strip('"')
        # 只导出非微软自带任务
        if name.startswith("\\Microsoft") or not name:
            continue
        safe_name = name.strip("\\").replace("\\", "_")
        xml_path = EXPORT_DIR / f"{safe_name}.xml"
        subprocess.run(
            ["schtasks", "/query", "/tn", name, "/xml"],
            stdout=open(xml_path, "w", encoding="utf-16"),
            check=False
        )
        print(f"导出: {name} -> {xml_path.name}")

重建任务

导入时用 /create /xml：

def import_tasks():
    for xml_file in EXPORT_DIR.glob("*.xml"):
        result = subprocess.run(
            ["schtasks", "/create", "/tn", xml_file.stem, "/xml", str(xml_file), "/f"],
            capture_output=True, text=True, encoding="gbk"
        )
        status = "OK" if result.returncode == 0 else "FAIL"
        print(f"[{status}] {xml_file.stem}")
        if result.returncode != 0:
            print(result.stderr)

关键坑点：

  • XML 里记录了原机器的用户名和路径，如果新系统用户名不同，导入会失败。需要手动改 XML 中的 <UserId> 和 <Command> 路径。
  • 任务默认以当前用户运行，涉及网络或高权限操作要勾选"使用最高权限运行"。
  • 触发器时间如果是过去的日期，任务不会立即执行，需要手动 schtasks /run /tn 任务名 测试。

导入后立即验证：

schtasks /query /tn "你的任务名" /v /fo LIST

第四步：迁移历史数据

数据迁移的核心是校验完整性。我一般用文件数量 + 总大小 + 关键文件哈希三重校验。

import hashlib
from pathlib import Path

def dir_signature(root: Path):
    """返回目录的文件数、总大小、合并哈希"""
    files = sorted(p for p in root.rglob("*") if p.is_file())
    total_size = sum(p.stat().st_size for p in files)
    h = hashlib.sha256()
    for p in files:
        h.update(p.name.encode())
        h.update(str(p.stat().st_size).encode())
    return len(files), total_size, h.hexdigest()

src = Path(r"D:\backup\data")
dst = Path(r"D:\data")

s_sig = dir_signature(src)
d_sig = dir_signature(dst)
print(f"源: {s_sig}")
print(f"目标: {d_sig}")
print("一致" if s_sig == d_sig else "不一致，需排查")

如果数据量不大（几 GB 以内），直接复制即可。如果涉及 SQLite 数据库，注意：

  • 复制前确保没有进程占用
  • 用 sqlite3 db.sqlite ".backup backup.sqlite" 做热备份更安全
  • 迁移后跑一次 PRAGMA integrity_check;

对于 Parquet/CSV 这类历史行情数据，迁移后建议按日期范围抽样校验：

import pandas as pd

df = pd.read_parquet(r"D:\data\history\BTCUSDT_1h.parquet")
print(df.shape)
print(df.index.min(), df.index.max())
print(df.isna().sum())

第五步：验证各模块功能

到这一步，文件都在了，但能不能跑是另一回事。我按模块逐个验证，写一个统一的检查脚本：

import importlib
import subprocess
import sys
from pathlib import Path

CHECKS = [
    ("数据读取", "check_data"),
    ("策略模块", "check_strategy"),
    ("回测引擎", "check_backtest"),
    ("定时任务", "check_tasks"),
]

def run_check(name, func_name):
    try:
        mod = importlib.import_module(func_name)
        ok = mod.run()
        print(f"[{'OK' if ok else 'FAIL'}] {name}")
        return ok
    except Exception as e:
        print(f"[ERROR] {name}: {e}")
        return False

if __name__ == "__main__":
    results = [run_check(n, f) for n, f in CHECKS]
    print(f"\n通过 {sum(results)}/{len(results)}")

每个 check_xxx.py 做具体验证，例如：

# check_data.py
def run():
    import pandas as pd
    from pathlib import Path
    files = list(Path(r"D:\data\history").glob("*.parquet"))
    if not files:
        return False
    df = pd.read_parquet(files[0])
    return len(df) > 0 and not df.empty

验证要点：

模块 验证方法
数据 读取首尾文件，检查行数、时间范围、空值
策略 用固定输入跑一次，对比输出是否符合预期
回测 跑一段已知结果的历史区间，核对收益指标
定时任务 手动触发一次，看日志是否正常输出
通知 发一条测试消息到 Telegram/邮件

日志目录也要检查，确认脚本有写入权限：

from pathlib import Path
log_dir = Path(r"D:\logs")
log_dir.mkdir(exist_ok=True)
test_file = log_dir / "recovery_test.log"
test_file.write_text("test", encoding="utf-8")
print("日志可写" if test_file.exists() else "日志不可写")

常见问题

1. schtasks 导入报"访问被拒绝"

用管理员权限打开终端再执行。或者检查 XML 里的 <RunLevel> 是否为 HighestAvailable。

2. 中文乱码

subprocess 调用 schtasks 时指定 encoding="gbk"，Windows 命令行默认 GBK 编码。

3. 依赖装完但 import 失败

多半是虚拟环境没激活，或者装到了另一个 Python 版本下。用 where python 和 sys.executable 确认路径。

4. 定时任务执行了但脚本没输出

检查任务里的"起始于"路径。相对路径在任务计划里是相对于 C:\Windows\System32，必须写绝对路径。

5. 数据文件时间戳错乱

用 shutil.copy2 而不是 copy，前者保留元数据。

收尾：把流程脚本化

上面每一步我都写成了独立脚本，放在 D:\scripts\recovery\ 下，用 main.py 串起来：

# main.py
from copy_scripts import run as copy_run
from install_deps import run as deps_run
from import_tasks import run as tasks_run
from verify_all import run as verify_run

def main():
    print("=== 1. 复制脚本 ===")
    copy_run()
    print("=== 2. 安装依赖 ===")
    deps_run()
    print("=== 3. 重建定时任务 ===")
    tasks_run()
    print("=== 4. 验证 ===")
    verify_run()

if __name__ == "__main__":
    main()

下次重装，一条命令跑完，剩下的只是排查个别报错。恢复流程本身也是代码，值得像策略一样维护和迭代。
