增量代码备份方案设计：版本管理最佳实践

2026-10-08 系统运维

在量化交易项目中,策略代码的迭代频率远高于普通业务系统。一个因子权重的微调、一段风控逻辑的修改,都可能直接影响实盘表现。如果没有可靠的备份机制,一次误操作就可能让数周的优化工作付诸东流。

Git 当然可以做版本管理,但实盘服务器上往往有诸多限制:不能随意推到远程仓库、不希望暴露策略细节、或者干脆就是离线环境。这时候,一套轻量的本地增量备份方案就很有必要。

本文分享一套我在多个量化项目中使用的备份方案,核心思路很简单:

  • 每次代码优化完成后,自动打包备份到指定目录
  • 命名规则:v{N}_{日期}_简述
  • 用 CHANGELOG.md 记录每次变更
  • 支持快速恢复

一、目录结构设计

先看整体结构,后面所有脚本都围绕它展开:

project/
├── strategy/              # 实际运行的代码
│   ├── main.py
│   └── ...
├── backups/               # 备份根目录
│   ├── v1_20240115_初始版本/
│   ├── v2_20240118_加入动量因子/
│   └── v3_20240122_修复止损逻辑/
├── CHANGELOG.md           # 变更日志
└── backup.py              # 备份脚本

备份目录里存的是完整快照,不是 diff。原因很直接:量化策略代码量通常不大(几千行级别),全量快照占用可控,恢复时零心智负担。真正的"增量"体现在只备份变更过的版本,而不是在文件层面做 delta 压缩。

二、备份脚本设计

核心脚本 backup.py 需要完成几件事:读取当前版本号、生成备份目录名、复制代码、更新 CHANGELOG。

# backup.py
import os
import re
import shutil
import argparse
from datetime import datetime
from pathlib import Path

PROJECT_ROOT = Path(__file__).parent.resolve()
SOURCE_DIR = PROJECT_ROOT / "strategy"
BACKUP_ROOT = PROJECT_ROOT / "backups"
CHANGELOG = PROJECT_ROOT / "CHANGELOG.md"

# 需要排除的文件/目录
EXCLUDE = {".git", "__pycache__", ".pytest_cache", ".idea", ".vscode"}


def get_latest_version() -> int:
    """扫描 backups 目录,返回当前最大版本号"""
    if not BACKUP_ROOT.exists():
        return 0
    pattern = re.compile(r"^v(\d+)_")
    versions = []
    for name in BACKUP_ROOT.iterdir():
        if name.is_dir():
            m = pattern.match(name.name)
            if m:
                versions.append(int(m.group(1)))
    return max(versions) if versions else 0


def make_backup_dir(version: int, desc: str) -> Path:
    """生成备份目录,格式 v{N}_{日期}_{简述}"""
    date_str = datetime.now().strftime("%Y%m%d")
    # 简述中的空格替换为下划线,避免路径问题
    safe_desc = re.sub(r"\s+", "_", desc.strip())
    dir_name = f"v{version}_{date_str}_{safe_desc}"
    target = BACKUP_ROOT / dir_name
    target.mkdir(parents=True, exist_ok=False)
    return target


def copy_source(target: Path):
    """复制源代码,忽略排除项"""
    def ignore(directory, files):
        return [f for f in files if f in EXCLUDE]

    shutil.copytree(SOURCE_DIR, target / "strategy", ignore=ignore)


def update_changelog(version: int, desc: str):
    """在 CHANGELOG.md 顶部插入新条目"""
    date_str = datetime.now().strftime("%Y-%m-%d %H:%M")
    entry = f"## v{version} - {date_str}\n\n- {desc}\n\n"

    if CHANGELOG.exists():
        content = CHANGELOG.read_text(encoding="utf-8")
    else:
        content = "# CHANGELOG\n\n"

    # 保留标题,新条目插在标题之后
    if content.startswith("# CHANGELOG"):
        header, _, body = content.partition("\n\n")
        new_content = f"{header}\n\n{entry}{body}"
    else:
        new_content = entry + content

    CHANGELOG.write_text(new_content, encoding="utf-8")


def backup(desc: str) -> Path:
    if not SOURCE_DIR.exists():
        raise FileNotFoundError(f"源码目录不存在: {SOURCE_DIR}")

    next_version = get_latest_version() + 1
    target = make_backup_dir(next_version, desc)
    copy_source(target)
    update_changelog(next_version, desc)

    print(f"[OK] 已备份到: {target}")
    print(f"[OK] 版本号: v{next_version}")
    return target


if __name__ == "__main__":
    parser = argparse.ArgumentParser(description="增量代码备份")
    parser.add_argument("-m", "--message", required=True, help="本次变更简述")
    args = parser.parse_args()
    backup(args.message)

使用方式:

python backup.py -m "加入动量因子,回测夏普提升至2.1"

脚本会自动生成 backups/v4_20240122_加入动量因子.../ 这样的目录,并在 CHANGELOG 顶部插入记录。

关键设计点

1. 版本号从目录扫描得出,而非存文件

用 get_latest_version() 扫描目录,避免了"版本号文件丢失导致冲突"的问题。备份目录本身就是版本号的事实来源。

2. 简述中的空格处理

Windows、Linux 对路径中的空格处理不一致,统一替换成下划线,减少后续脚本解析的麻烦。

3. 排除项集中管理

__pycache__、.git 这类目录没必要备份,反而会让备份体积膨胀。集中定义 EXCLUDE 集合,后续维护方便。

三、版本号管理策略

版本号不是随便加的,推荐遵循以下规则:

场景 示例 说明
策略逻辑变更 v5 → v6 因子、信号、仓位规则改动
参数微调 v6 → v7 阈值、周期等参数调整
Bug 修复 v7 → v8 不影响策略逻辑
重构 v8 → v9 结构变化但行为一致

不建议做 v1.2.3 这种语义化版本。 量化策略的迭代往往是线性的、频繁的,主版本号一路递增反而清晰。真正重要的信息在日期和简述里,而不是版本号本身。

如果确实需要区分"大版本"和"小版本",可以在简述中标注,比如:

v12_20240201_重构数据层[breaking]
v13_20240203_新增RSI因子

四、CHANGELOG 规范

CHANGELOG.md 是整个方案里最容易被忽视、但价值最高的部分。半年后回头看代码,你可能忘了为什么当初把止损从 2% 改成 1.5%,但 CHANGELOG 会告诉你。

推荐格式:

# CHANGELOG

## v8 - 2024-01-22 15:30

- 修复移动止损在跳空行情下未触发的问题
- 回测区间 2020-2023,最大回撤从 18% 降至 12%

## v7 - 2024-01-18 10:12

- 动量因子窗口从 20 日调整为 15 日
- 夏普从 1.8 提升至 2.1

## v6 - 2024-01-15 09:00

- 初始版本,双均线 + 动量组合

写 CHANGELOG 的三个原则:

  1. 写"为什么",不只写"做了什么"。"调整参数"是废话,"调整参数以降低震荡市中的假信号"才有价值。
  2. 带上量化结果。回测指标、实盘表现,这些数字才是判断变更好坏的依据。
  3. 一条记录只描述一件事。如果一次改了三个地方,拆成三条。

五、恢复流程

恢复比备份更需要谨慎,因为恢复操作往往是"救火"场景,容易出错。

5.1 查看可用版本

# list_versions.py
import re
from pathlib import Path

BACKUP_ROOT = Path("backups")
pattern = re.compile(r"^v(\d+)_(\d{8})_(.+)$")

for d in sorted(BACKUP_ROOT.iterdir()):
    if not d.is_dir():
        continue
    m = pattern.match(d.name)
    if m:
        v, date, desc = m.groups()
        print(f"v{v:<4} {date}  {desc}")

输出:

v1    20240115  初始版本
v2    20240118  加入动量因子
v3    20240122  修复止损逻辑

5.2 安全恢复脚本

直接 shutil.copytree 覆盖现有代码风险很大。推荐先备份当前状态,再恢复目标版本:

# restore.py
import shutil
import argparse
from pathlib import Path
from datetime import datetime

PROJECT_ROOT = Path(__file__).parent.resolve()
SOURCE_DIR = PROJECT_ROOT / "strategy"
BACKUP_ROOT = PROJECT_ROOT / "backups"


def restore(version: int):
    # 1. 找到目标备份
    candidates = [d for d in BACKUP_ROOT.iterdir()
                  if d.is_dir() and d.name.startswith(f"v{version}_")]
    if not candidates:
        raise FileNotFoundError(f"未找到 v{version} 的备份")
    target = candidates[0]

    # 2. 先备份当前状态,防止误操作
    ts = datetime.now().strftime("%Y%m%d_%H%M%S")
    safety = BACKUP_ROOT / f"_pre_restore_{ts}"
    shutil.copytree(SOURCE_DIR, safety)
    print(f"[SAFE] 当前状态已备份到: {safety}")

    # 3. 清空并恢复
    shutil.rmtree(SOURCE_DIR)
    shutil.copytree(target / "strategy", SOURCE_DIR)
    print(f"[OK] 已恢复到 v{version}: {target.name}")


if __name__ == "__main__":
    parser = argparse.ArgumentParser()
    parser.add_argument("-v", "--version", type=int, required=True)
    args = parser.parse_args()
    restore(args.version)

使用:

python restore.py -v 7

这个脚本的关键是先备份再覆盖。哪怕恢复错了版本,还能从 _pre_restore_* 目录里找回来。

5.3 恢复后的验证

恢复完不要急着跑实盘,至少做三件事:

  1. 对比 strategy/ 和备份目录的文件哈希,确认复制完整
  2. 跑一遍回测,确认指标符合 CHANGELOG 记录
  3. 检查配置文件、依赖版本是否匹配
# verify.py
import hashlib
from pathlib import Path

def dir_hash(path: Path) -> str:
    h = hashlib.md5()
    for f in sorted(path.rglob("*")):
        if f.is_file() and "__pycache__" not in str(f):
            h.update(f.read_bytes())
    return h.hexdigest()

a = dir_hash(Path("strategy"))
b = dir_hash(Path("backups/v7_20240118_加入动量因子/strategy"))
print("一致" if a == b else "不一致,请检查")

六、自动化集成

手动跑 backup.py 容易忘。推荐两种自动化方式:

方式一:Git hook

在 .git/hooks/post-commit 里调用备份脚本,每次 commit 自动生成备份。适合用 Git 做主要版本管理的项目。

方式二:定时任务

用 schedule 库或系统 cron,每天收盘后自动备份一次:

import schedule
import time
from backup import backup

schedule.every().day.at("15:30").do(
    backup, desc="每日自动备份"
)

while True:
    schedule.run_pending()
    time.sleep(60)

方式三:文件监听

用 watchdog 监听 strategy/ 目录,检测到 .py 文件保存后延迟 5 分钟自动备份,避免频繁触发。

七、几个实践中的坑

1. 备份目录别放在项目内

如果 backups/ 在项目根目录,而项目本身又被 Git 管理,容易造成递归备份。建议在 .gitignore 里排除 backups/,或者干脆把备份目录放到项目外。

2. 大文件要排除

如果项目里有数据文件、模型文件(几百 MB 甚至 GB),一定要加进 EXCLUDE,否则备份会失控。

3. 定期清理旧版本

保留全部版本只适合早期。稳定运行后,建议保留最近 20 个版本 + 每个月的第一个版本:

def cleanup(keep_recent=20):
    dirs = sorted(
        [d for d in BACKUP_ROOT.iterdir() if d.is_dir()],
        key=lambda d: d.stat().st_mtime,
        reverse=True
    )
    for d in dirs[keep_recent:]:
        shutil.rmtree(d)
        print(f"[CLEAN] 删除: {d.name}")

4. CHANGELOG 不要自动生成

脚本只负责插入模板,具体内容必须人工写。自动生成的 CHANGELOG 等于没有 CHANGELOG。

八、方案总结

这套方案的核心不是技术复杂度,而是约束:

  • 强制每次变更都有简述
  • 强制每次变更都进 CHANGELOG
  • 强制恢复前先备份当前状态

工具本身简单,难的是坚持。当你在半年后需要回滚一个策略、或者向别人解释某次改动的原因时,这套机制的价值就会体现出来。

代码量不到 200 行,依赖只有标准库,可以直接嵌入任何 Python 项目。对于量化策略这种"改动频繁、后果严重、环境受限"的场景,比引入重型工具更实用。
