反事实重放回测：如果当时有熔断会怎样

2026-10-28 量化回测

问题的本质

假设你有一套跑了两年的实盘策略，交易记录完整。现在你想知道：如果当初就加上"单日亏损超过2%停止开新仓"这条规则，历史曲线会怎么变？

普通回测回答不了这个问题。因为你的历史交易是在旧规则下发生的——每笔开仓的时间、价格、仓位，都是旧规则的产物。你重新跑一遍回测，用的是历史K线加新规则，但策略的参数、信号逻辑、甚至你对市场的判断，都已经和当初不一样了。这不是"如果当时"，这是"如果现在"。

反事实重放（counterfactual replay）走的是另一条路：不改策略，只改规则，把真实发生的交易记录当作输入，在重放时叠加新规则。 被规则拦截的开仓直接剔除，对应的平仓也剔除，然后处理拦截带来的连锁影响。

这比重新回测更接近"如果当时"的语义，因为它保留了真实交易的所有细节——真实的成交价、真实的滑点、真实的持仓时长。

重放引擎的设计

核心数据结构很简单：一笔交易（trade）包含开仓时间、开仓价、平仓时间、平仓价、方向、数量。重放引擎按时间顺序遍历这些交易，对每笔开仓应用新规则，决定放行还是拦截。

from dataclasses import dataclass
from datetime import datetime
from typing import Callable, Optional
import pandas as pd

@dataclass
class Trade:
    open_time: datetime
    open_price: float
    close_time: datetime
    close_price: float
    direction: int      # 1 多, -1 空
    size: float

    @property
    def pnl(self) -> float:
        return (self.close_price - self.open_price) * self.direction * self.size

规则接口设计成一个函数，输入是当前交易和重放状态（已实现的盈亏、当日累计亏损等），输出是放行或拦截：

@dataclass
class ReplayState:
    realized_pnl: float = 0.0
    daily_pnl: float = 0.0
    current_day: Optional[datetime] = None
    blocked_count: int = 0

Rule = Callable[[Trade, ReplayState], bool]  # True = 放行

重放主循环：

def replay(trades: list[Trade], rules: list[Rule]) -> tuple[list[Trade], ReplayState]:
    state = ReplayState()
    kept = []
    for t in sorted(trades, key=lambda x: x.open_time):
        # 跨日重置
        day = t.open_time.date()
        if state.current_day != day:
            state.current_day = day
            state.daily_pnl = 0.0

        if all(rule(t, state) for rule in rules):
            kept.append(t)
            state.realized_pnl += t.pnl
            state.daily_pnl += t.pnl
        else:
            state.blocked_count += 1
    return kept, state

到这里还只是"过滤"，真正的难点在下一步。

连锁效应：拦截不是孤立的

被拦截的一笔开仓，会改变后续的状态。最典型的是日内亏损熔断：原本第3笔交易亏损触发了熔断，第4、5笔被拦截；但如果第1笔就被拦截了，第3笔可能根本不会触发熔断，第4、5笔就该放行。

这就是连锁效应（cascading effect）。上面的朴素实现有个致命问题：它用原始交易的盈亏去更新 daily_pnl，但原始交易的盈亏是基于"所有交易都发生"的路径。一旦有交易被拦截，后续的 daily_pnl 轨迹就错了。

正确的做法是：状态只由放行的交易驱动，规则判断基于重放后的状态，而不是原始状态。 上面代码其实已经做到了这一点——state.daily_pnl 只在放行时累加。但还有一个隐含假设需要显式处理：被拦截交易的平仓价，是否还应该用来更新状态？

答案是不应该。被拦截的交易从未发生，它的盈亏不该进入任何状态。但这里有个微妙之处：如果一笔交易在开仓时被拦截，它的平仓时间点之后的市场状态（比如波动率、价格水平）在现实中确实变了，但重放引擎不模拟市场，只模拟交易流。所以平仓事件也必须一并剔除。

def replay_with_cascade(trades, rules):
    state = ReplayState()
    kept = []
    blocked_ids = set()

    for t in sorted(trades, key=lambda x: x.open_time):
        day = t.open_time.date()
        if state.current_day != day:
            state.current_day = day
            state.daily_pnl = 0.0

        # 如果这笔交易依赖的前序交易被拦截，视情况处理
        # 这里假设交易相互独立，只处理状态依赖
        if all(rule(t, state) for rule in rules):
            kept.append(t)
            state.realized_pnl += t.pnl
            state.daily_pnl += t.pnl
        else:
            blocked_ids.add(id(t))
            state.blocked_count += 1

    return kept, state, blocked_ids

如果策略有仓位依赖（比如同时最多持仓N笔，或后一笔仓位是前一笔的加仓），连锁效应会更复杂：拦截一笔会释放仓位额度，让后续原本被仓位限制挡住的交易得以发生。这种场景需要把规则引擎和仓位管理耦合起来，重放时维护一个"虚拟持仓簿"，而不是简单地过滤列表。

一个实用的折中：把重放分成两层。 第一层只处理"状态型规则"（日内亏损、连续亏损次数、单日交易笔数上限），这类规则的连锁效应可以通过顺序重放自然处理。第二层处理"路径型规则"（仓位上限、资金占用），这类需要模拟持仓簿，实现成本高，先标注为不支持，在报告里明确说明。

口径选择：1小时K线现价近似

重放需要价格。真实交易记录里有开仓价和平仓价，但规则判断往往需要开仓时刻的现价——比如"当前浮亏超过X就禁止加仓"，或者"日内已实现亏损按当前价折算"。

最精确的口径是用tick或逐笔数据重算，但成本高。务实的选择是1小时K线收盘价近似现价：

def load_hourly_close(symbol: str, start, end) -> pd.Series:
    # 假设已有本地K线库
    df = pd.read_parquet(f"data/{symbol}_1h.parquet")
    df = df[(df.index >= start) & (df.index <= end)]
    return df["close"]

def price_at(series: pd.Series, ts: datetime) -> float:
    # 取 ts 之前最近的1小时收盘价
    idx = series.index.searchsorted(ts, side="right") - 1
    return float(series.iloc[max(idx, 0)])

这个近似的误差来源有两个：一是小时内价格波动，开仓发生在10:15，用10:00的收盘价，可能偏差几个tick；二是跳空，如果开仓在整点后第一分钟，前一根K线的收盘价可能已经过时。

对日内风控规则来说，这个误差通常可接受——熔断阈值是2%，K线近似误差在0.1%量级，不会改变大多数判断。但如果规则阈值本身很窄（比如0.3%的移动止损），就必须用更细的数据。

一个改进：用开仓价本身作为现价的代理。因为开仓价是真实成交价，比K线收盘价更接近"那一刻的市场"。缺点是无法得到开仓前的浮盈状态。折中方案是：开仓前的状态用K线近似，开仓后的状态用成交价，两者拼接。

局限说明

反事实重放不是万能药，有三个必须写进报告的限制：

第一，不模拟资金占用变化。 被拦截的交易不占用资金，理论上这些资金可以用于其他交易，或者影响后续交易的仓位大小。重放引擎假设资金无限、仓位独立，所以它回答的是"如果这些交易没发生"，而不是"如果这些资金重新配置"。后者需要完整的组合级模拟。

第二，K线近似现价的误差。 上面已经讨论过，误差量级取决于规则阈值和数据粒度。报告里应该给出一个敏感性分析：把阈值上下浮动20%，看结论是否稳健。

第三，幸存者偏差的反向版本。 原始交易记录本身是旧规则的产物。如果旧规则曾经拦截过某些交易，这些交易根本不在记录里，重放也无法"恢复"它们。所以重放只能回答"在已发生的交易集合上，新规则会改变什么"，不能回答"新规则会创造哪些新交易"。

一个完整的调用示例

def daily_loss_limit(limit_pct: float, capital: float) -> Rule:
    def rule(t: Trade, s: ReplayState) -> bool:
        return s.daily_pnl > -limit_pct * capital
    return rule

def max_trades_per_day(n: int) -> Rule:
    def rule(t: Trade, s: ReplayState) -> bool:
        # 需要额外维护当日计数，这里简化
        return True
    return rule

trades = load_trades("trades.parquet")  # 你的真实交易记录
rules = [daily_loss_limit(0.02, capital=1_000_000)]

kept, state, blocked = replay_with_cascade(trades, rules)
print(f"原始 {len(trades)} 笔, 保留 {len(kept)} 笔, 拦截 {state.blocked_count} 笔")
print(f"原始盈亏 {sum(t.pnl for t in trades):.2f}, 重放盈亏 {state.realized_pnl:.2f}")

输出会直接告诉你：加上这条熔断后，历史盈亏从多少变成多少，拦截了多少笔交易。再叠加一个按日聚合的对比图，就能看到熔断在哪些交易日真正起了作用。

反事实重放的价值不在于精确预测，而在于用真实数据量化规则的边际影响。它比重新回测更诚实，因为它承认"历史不可重来"，只做局部替换。对于风控规则的评估，这已经够用了。
