给策略做减法：多空贡献拆分后，我把做空腿直接砍了

2026-11-16 量化策略

先上数据。EMA20/50 双向趋势跟随，7 个主流币，4 年日线数据，固定仓位、无杠杆、手续费按 taker 双边计算：

指标 数值
累计收益 +265.8%
最大回撤 33.1%
交易笔数 438
t 统计量 1.61
p 值 0.107

收益数字很好看，但 t=1.61、p=0.107，在常规显著性门槛下不显著。这意味着什么？意味着这 +265.8% 有相当概率是运气，而不是策略真的有效。

问题在于：一个双向策略，做多腿和做空腿混在一起，你根本不知道收益是谁挣的、亏损是谁亏的。混合统计量会把一个有效的方向和无效的方向平均掉，也可能让一个本来显著的信号变得不显著。

所以第一步不是调参，不是加过滤，是拆开看。

二、多空贡献拆分：同一引擎，按方向过滤

拆分的核心原则：不要写两套策略代码。两套代码意味着两套 bug、两套逻辑漂移，最后你连对比的基础都不存在。

正确做法是：同一个回测引擎，跑同一套信号逻辑，只在成交记录层面按方向过滤，分别统计。

先看信号生成部分。EMA 交叉逻辑本身是方向对称的：

import pandas as pd
import numpy as np

def generate_signals(df: pd.DataFrame, fast=20, slow=50) -> pd.DataFrame:
    """
    df 需包含 'close' 列，索引为时间。
    返回带 ema_fast / ema_slow / signal 的 DataFrame。
    signal: 1 表示金叉后持多，-1 表示死叉后持空，0 表示空仓
    """
    out = df.copy()
    out["ema_fast"] = out["close"].ewm(span=fast, adjust=False).mean()
    out["ema_slow"] = out["close"].ewm(span=slow, adjust=False).mean()

    raw = np.where(out["ema_fast"] > out["ema_slow"], 1, -1)
    out["signal"] = pd.Series(raw, index=out.index).shift(1).fillna(0)
    return out

注意 shift(1)：信号在收盘后生成，下一根 K 线才生效，避免未来函数。这一步做错，后面所有拆分都是垃圾。

接下来是成交记录。关键设计是：每笔交易记录方向字段，而不是在开仓时就区分策略：

def run_backtest(df: pd.DataFrame, fee=0.0005) -> pd.DataFrame:
    """
    按 signal 持仓，signal 变化时换仓。
    返回逐笔成交记录 trades，含 direction / entry / exit / pnl。
    """
    df = df.copy()
    df["pos"] = df["signal"].fillna(0)
    df["pos_change"] = df["pos"].diff().fillna(df["pos"])

    trades = []
    entry_price, entry_time, direction = None, None, 0

    for ts, row in df.iterrows():
        if row["pos_change"] == 0:
            continue
        # 平掉旧仓
        if direction != 0 and entry_price is not None:
            exit_price = row["close"]
            gross = direction * (exit_price / entry_price - 1)
            net = gross - 2 * fee
            trades.append({
                "entry_time": entry_time,
                "exit_time": ts,
                "direction": direction,   # 1 多 / -1 空
                "entry": entry_price,
                "exit": exit_price,
                "pnl": net,
            })
        # 开新仓
        direction = int(row["pos"])
        entry_price = row["close"] if direction != 0 else None
        entry_time = ts if direction != 0 else None

    return pd.DataFrame(trades)

有了带 direction 的成交记录，拆分就是一行 groupby 的事：

def split_by_direction(trades: pd.DataFrame) -> dict:
    result = {}
    for name, d in [("long", 1), ("short", -1)]:
        sub = trades[trades["direction"] == d]
        pnl = sub["pnl"].values
        n = len(pnl)
        total = pnl.sum()
        # 单笔收益的 t 检验（零假设：均值 = 0）
        if n > 1:
            t_stat = pnl.mean() / (pnl.std(ddof=1) / np.sqrt(n))
        else:
            t_stat = np.nan
        result[name] = {
            "trades": n,
            "total_return": total,
            "avg_pnl": pnl.mean() if n else np.nan,
            "t_stat": t_stat,
        }
    return result

注意这里的 t 检验是对单笔收益率序列做的，不是对净值曲线做的。对单笔 pnl 做 t 检验，回答的是"这笔交易的期望收益是否显著大于 0"，这是判断方向是否有效的更直接口径。净值 t 检验会被复利和路径依赖污染，两者不要混用。

跑完，结果是：

方向 笔数 累计收益 t 统计量
做多腿 298 +295.7% 显著为正
做空腿 140 -37.9% -1.61

双向合计 +265.8%，做多腿单独就 +295.7%。也就是说，做空腿不仅亏了 37.9%，还把整体收益从 295.7% 拖到 265.8%，同时把整体显著性拉没了。做空腿的 t=-1.61，和双向整体的 t=1.61 数值上正好对称——这不是巧合，是混合样本稀释效应的直接体现：一个显著的正向信号，被一个不显著的负向信号平均后，变成了"正但不显著"。

三、为什么做空在加密趋势策略里难赚钱

拆出来看是结果，理解原因是决策的前提。做空腿在趋势跟随框架下亏钱，有三个结构性原因。

3.1 收益分布右偏

加密资产的长期收益分布是右偏的：上涨幅度大、持续时间长、少数极端行情贡献大部分涨幅；下跌则往往急促、时间短、幅度被快速修复。趋势跟随策略的盈利模式是"截断亏损、让利润奔跑"，这个模式天然适配右偏分布——做多腿能吃到长尾上涨，做空腿却只能吃到短促下跌，长尾在错误的一侧。

用代码量化这个偏态，比空谈直观：

def return_skew_stats(df: pd.DataFrame) -> pd.Series:
    r = df["close"].pct_change().dropna()
    return pd.Series({
        "mean": r.mean(),
        "skew": r.skew(),
        "kurt": r.kurt(),
        "p99": r.quantile(0.99),
        "p01": r.quantile(0.01),
        "up_down_ratio": r[r > 0].mean() / abs(r[r < 0].mean()),
    })

在样本上，日收益偏度为正，且 p99 的绝对幅度明显大于 p01。做多腿的盈利来自右尾，做空腿的盈利需要左尾，而左尾更薄。

3.2 插针与滑点不对称

做空腿对"插针"极其敏感。一根长上影线打穿止损，空单被扫出局，随后价格回落——方向判断对了，但仓位已经没了。做多腿遇到向下插针同样会被扫，但加密市场向上插针的频率和幅度整体更高，空单的止损被打掉的概率系统性偏高。

回测里这一点很难完全复现，因为回测用的是收盘价或固定滑点。实盘里空单的滑点分布是右偏的（极端行情下流动性瞬间消失），回测按对称滑点处理，等于系统性高估了做空腿的表现。也就是说，-37.9% 这个数字还算乐观的。

3.3 资金费率与持有成本

永续合约做空要付资金费率。在趋势性上涨行情中，资金费率长期为正，空头持续付费。这部分成本在纯价格回测里如果没建模，做空腿的真实表现会更差。做多腿在同样行情下是收资金费的一方，成本结构完全相反。

三个原因叠加，结论很清楚：在加密趋势跟随框架里，做空腿不是"少赚"，是结构性劣势。它不是参数没调好，是方向本身和这个市场的收益分布不匹配。

四、决策：砍掉做空腿，改成单向只做多

拆分结果出来后，决策其实没有太多纠结空间。改法很具体：

  • 金叉开多
  • 死叉平多
  • 不反手

第三条是关键。"不反手"意味着死叉时清仓离场，而不是反向开空。这砍掉的正是那 140 笔亏损交易，同时保留了做多腿的 298 笔。

代码上，只需要在信号层把 -1 映射为 0：

def long_only_signal(df: pd.DataFrame, fast=20, slow=50) -> pd.DataFrame:
    out = generate_signals(df, fast, slow)
    # 死叉不反手，直接空仓
    out["signal"] = out["signal"].clip(lower=0)
    return out

一行 clip(lower=0)。策略从双向变单向，逻辑复杂度下降，代码分支减少，实盘出错面收窄——这是"做减法"的直接收益。

改完重跑，做多腿的统计量保持 +295.7% / 298 笔 / 显著为正。但这里必须诚实：这是样本内拆分出来的结果，不是样本外验证。拆方向本身是一种多重比较，你从两个方向里挑了一个好的，天然带选择偏差。

所以最终日志里我写的是：

单向做多版本：收益为正且单笔 t 检验显著，但样本内方向选择存在偏差，定位为观察盘，不直接上线。

五、纪律：验证不达标就降级，而不是硬上

这次决策里，比"砍掉做空腿"更重要的是砍掉之后怎么处理。

一个常见的错误路径是：拆分发现做多腿显著 → 直接改成单向 → 上线。这跳过了样本外验证，把样本内的方向选择当成了策略结论。t 检验显著只说明"在这个样本里这个方向的单笔收益均值不为零"，不说明"未来这个方向继续有效"。

我的处理是把策略状态分级：

状态 条件 处理
上线盘 样本外 t 检验显著 + 回撤可接受 小仓位实盘
观察盘 样本内显著、样本外未验证 纸面跟踪，记录每日信号
淘汰 样本内外均不显著 归档

单向做多版本当前处于观察盘：纸面跟踪，每日记录信号和理论成交，等样本外数据积累到足够笔数再做一次 t 检验。达标再升级，不达标就归档。这个过程可能需要几个月，但比拿真金白银去验证一个带选择偏差的结论便宜得多。

这个纪律的核心是：显著性检验是准入门槛，不是上线许可证。p<0.05 只说明"值得继续观察"，不说明"可以下注"。把"验证不达标"和"策略无效"区分开，前者降级观察，后者直接淘汰，中间态才是大多数策略的真实位置。

六、小结

这次迭代没有加任何新指标、新过滤、新参数。做的是三件事：

  1. 拆分：同一引擎按方向过滤成交记录，把混合统计量拆成两个独立方向的口径。
  2. 归因：做空腿 -37.9%、t=-1.61，是拖累项而非贡献项；原因在收益右偏、插针不对称、资金费率三个结构性因素。
  3. 减法：clip(lower=0) 砍掉做空腿，策略从双向变单向，代码和逻辑同时变简单。

收益数字从 +265.8% 变成 +295.7%，但真正的收获不是这 30 个百分点，而是知道了这 295.7% 是从哪来的、以及它为什么还不算数。一个说不清贡献来源的策略，收益再高也只是黑箱；拆开之后哪怕数字变小，你也拿到了可以继续迭代的基础。

策略优化的方向不总是加东西。很多时候，把不贡献的部分砍掉，剩下的才看得清。
