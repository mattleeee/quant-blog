PushPlus微信推送系统搭建：从零到自动通知

2026-08-17 Python自动化

量化交易的日常，最烦的不是写策略，而是盯盘。信号出来了人不在，策略再准也没用。所以，通知系统是量化自动化里绕不开的一环。今天直接讲PushPlus——一个能把消息推到微信的HTTP API服务，配合Python，五分钟搭完整个推送链路。

为什么选PushPlus

先摆事实：PushPlus支持文本、Markdown、HTML、JSON等格式，免费额度足够个人量化用，而且不需要装App、不需要公众号认证，只要扫码关注一个服务号就能收消息。对比Server酱，PushPlus的模板消息和批量推送功能更灵活；对比Telegram Bot，国内网络环境友好得多。

第一步：注册并获取Token

打开PushPlus官网（pushplus.plus），用微信扫码登录，登录后在首页就能看到你的token，一串32位的十六进制字符串。这串token就是你的身份凭证，所有推送请求都靠它。

注意：token等同于你的微信接收权限，别提交到公开仓库。建议存到环境变量或本地配置文件里。

第二步：写第一个推送函数

PushPlus的API极其简单，一个POST请求搞定。先看最基础的文本推送：

import requests

def send_text(token: str, title: str, content: str) -> dict:
    """
    发送文本消息到微信

    Args:
        token: PushPlus的token
        title: 消息标题，最长100字符
        content: 消息内容，最长5000字符

    Returns:
        API返回的JSON字典
    """
    url = "https://www.pushplus.plus/send"
    payload = {
        "token": token,
        "title": title,
        "content": content,
        "template": "txt"
    }

    resp = requests.post(url, json=payload, timeout=10)
    resp.raise_for_status()
    return resp.json()

# 使用示例
if __name__ == "__main__":
    TOKEN = "你的token"
    result = send_text(TOKEN, "测试消息", "这是第一条Python推送")
    print(result)
    # 正常返回: {'code': 200, 'msg': '请求成功', 'data': '发送成功'}

注意resp.raise_for_status()，HTTP层面错误直接抛异常。而PushPlus业务层面的错误（比如token无效）会返回code非200的JSON，后面统一处理。

第三步：消息类型详解

PushPlus支持多种template参数，不同模板决定了content的渲染方式。

3.1 文本模板（txt）

上面已经演示过，纯文本，适合短通知。

3.2 Markdown模板（markdown）

这是量化场景最常用的。收益曲线、持仓变动、策略信号，用Markdown排版后，微信里直接渲染成富文本。

def send_markdown(token: str, title: str, content_md: str) -> dict:
    """
    发送Markdown格式消息
    """
    url = "https://www.pushplus.plus/send"
    payload = {
        "token": token,
        "title": title,
        "content": content_md,
        "template": "markdown"
    }

    resp = requests.post(url, json=payload, timeout=10)
    resp.raise_for_status()
    return resp.json()

# 实战示例：推送策略信号
md_content = """
### 交易信号

**品种**: BTC/USDT  
**方向**: 做多  
**入场价**: 65000  
**止损价**: 64000  
**止盈价**: 68000  

> 信号时间: 2024-01-15 14:30:00  
> 信号强度: 强（RSI超卖+MACD金叉）
"""

send_markdown(TOKEN, "【策略信号】BTC做多", md_content)

3.3 HTML模板（html）

如果要更复杂的排版，比如表格、颜色标注，用HTML模板。注意PushPlus的HTML模板不支持外部CSS，只能用内联样式。

3.4 JSON模板（json）

这个很有用——配合微信小程序的"推送Plus"插件，可以把结构化数据渲染成卡片。不过日常量化通知，Markdown已经够用了。

第四步：标题命名规范

标题是用户第一眼看到的东西，直接影响打开率。做量化推送，我总结三条铁律：

  1. 前缀标明系统：【策略A】、【风控】、【交易】，微信通知栏只显示前几个字，前缀必须一眼识别。
  2. 时间放结尾：【策略A】BTC做多信号 - 14:30，方便回溯。
  3. 紧急度分级：风控类加【紧急】，普通信号不加。PushPlus本身没有级别区分，靠标题约定。

第五步：错误处理

推送失败是常态，网络抖动、API限流、token过期。写一个健壮的推送函数，必须考虑这些。

import time
import logging
from typing import Optional

logging.basicConfig(level=logging.INFO)
logger = logging.getLogger(__name__)

class PushPlusError(Exception):
    """PushPlus推送异常"""
    pass

def send_with_retry(token: str, title: str, content: str, 
                    template: str = "txt", max_retries: int = 3) -> Optional[dict]:
    """
    带重试机制的推送函数

    Args:
        token: PushPlus token
        title: 标题
        content: 内容
        template: 消息模板
        max_retries: 最大重试次数

    Returns:
        成功返回响应dict，失败返回None
    """
    url = "https://www.pushplus.plus/send"
    payload = {
        "token": token,
        "title": title,
        "content": content,
        "template": template
    }

    for attempt in range(max_retries):
        try:
            resp = requests.post(url, json=payload, timeout=10)
            resp.raise_for_status()

            result = resp.json()
            if result.get("code") != 200:
                # 业务错误，比如token无效，重试也没用
                if result.get("code") in (401, 403):
                    raise PushPlusError(f"认证失败: {result.get('msg')}")
                # 其他业务错误，可能是内容超长，重试也无意义
                logger.error(f"推送业务错误: {result}")
                return None

            logger.info(f"推送成功: {title}")
            return result

        except requests.RequestException as e:
            logger.warning(f"网络错误 (尝试 {attempt + 1}/{max_retries}): {e}")
            if attempt < max_retries - 1:
                time.sleep(2 ** attempt)  # 指数退避
            else:
                logger.error(f"推送最终失败: {title}")
                return None

    return None

这个函数做了三件事： - HTTP异常重试，指数退避（1s、2s、4s） - 认证错误直接抛出异常，不浪费重试次数 - 记录完整日志，方便事后排查

第六步：消息模板设计

模板的意义在于统一格式、减少重复代码。用Python的str.format或f-string做简单模板，复杂场景用jinja2。

from string import Template

# 用string.Template做简单模板
SIGNAL_TEMPLATE = Template("""
### $strategy_name 交易信号

**品种**: $symbol  
**方向**: $direction  
**入场价**: $entry_price  
**止损价**: $stop_loss  
**止盈价**: $take_profit  

> 信号时间: $signal_time  
> 信号强度: $strength
""")

def format_signal_message(signal: dict) -> str:
    """将信号字典格式化为Markdown字符串"""
    return SIGNAL_TEMPLATE.substitute(
        strategy_name=signal.get("strategy", "未知策略"),
        symbol=signal.get("symbol", "未知品种"),
        direction=signal.get("direction", "观望"),
        entry_price=signal.get("entry", "-"),
        stop_loss=signal.get("stop", "-"),
        take_profit=signal.get("target", "-"),
        signal_time=signal.get("time", "-"),
        strength=signal.get("strength", "-")
    )

用Template.substitute比f-string好在：字段缺失时不会崩溃，而是报KeyError，方便排查数据源问题。

第七步：完整实战——策略信号自动推送

把上面的模块串起来，做一个完整的推送服务。假设你有一个策略信号生成函数get_signal()，返回一个dict。

import schedule
import time as time_module

class QuantNotifier:
    """量化信号推送器"""

    def __init__(self, token: str):
        self.token = token
        self.last_signal_time = None
        self.signal_count = 0

    def push_signal(self, signal: dict) -> bool:
        """
        推送交易信号，带去重逻辑

        Args:
            signal: 信号字典

        Returns:
            是否推送成功
        """
        # 简单去重：同一分钟内的相同信号不重复推送
        current_time = signal.get("time")
        if current_time == self.last_signal_time:
            logger.info("重复信号，跳过推送")
            return False

        content_md = format_signal_message(signal)
        title = f"【{signal['strategy']}】{signal['symbol']} {signal['direction']}"

        result = send_with_retry(
            self.token,
            title,
            content_md,
            template="markdown"
        )

        if result:
            self.last_signal_time = current_time
            self.signal_count += 1
            logger.info(f"已推送第 {self.signal_count} 条信号")
            return True

        return False

    def push_daily_report(self, stats: dict):
        """每日收盘统计推送"""
        report_md = f"""
### 今日交易统计

**总交易次数**: {stats.get('total_trades', 0)}  
**盈利次数**: {stats.get('win_trades', 0)}  
**胜率**: {stats.get('win_rate', 0):.2%}  
**累计盈亏**: {stats.get('pnl', 0):+.4f} USDT  

---
*报表生成时间: {time_module.strftime('%Y-%m-%d %H:%M:%S')}*
        """
        send_with_retry(
            self.token,
            "【日报】交易统计",
            report_md,
            template="markdown"
        )

# 使用示例
if __name__ == "__main__":
    notifier = QuantNotifier(TOKEN)

    # 模拟一个信号
    demo_signal = {
        "strategy": "双均线",
        "symbol": "ETH/USDT",
        "direction": "做空",
        "entry": 3200,
        "stop": 3300,
        "target": 3000,
        "time": "2024-01-15 14:30:00",
        "strength": "中等"
    }

    notifier.push_signal(demo_signal)

    # 每天下午4点推送日报
    schedule.every().day.at("16:00").do(notifier.push_daily_report, {"total_trades": 5, "win_trades": 3, "win_rate": 0.6, "pnl": 120.5})

    while True:
        schedule.run_pending()
        time_module.sleep(60)

常见坑与优化

1. 频率限制：PushPlus免费版有每分钟推送次数限制，实测约30次/分钟。高频策略建议做本地聚合，比如每分钟汇总一次信号再推。

2. 内容长度：文本模板上限5000字符，Markdown模板建议控制在3000字符内，微信渲染长文本会卡顿。

3. 时区问题：PushPlus服务器在UTC+8，如果你的策略服务器在UTC，时间字段要显式转换，否则推送记录的时间会差8小时。

4. 消息丢失：极端情况下API可能不返回任何响应（超时），send_with_retry里timeout=10设短一点，配合重试机制基本能保证送达。

5. 多策略管理：推荐每个策略一个独立token，这样在微信里可以按token归档，也可以单独屏蔽某个策略的通知。

整套系统搭下来，核心代码不超过100行。从信号产生到微信弹出通知，延迟在1-2秒内。后续可以扩展的方向：把推送封装成装饰器、接入消息队列做异步推送、或者用WebSocket实时推送行情异动。
