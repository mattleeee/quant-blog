任务执行成功后自动推送微信通知的方案

2026-08-12 定时任务

定时任务跑完，结果躺在日志文件里没人看，等于白跑。尤其量化策略，信号出了没及时看到，机会就过去了。这篇文章分享一个轻量方案：用 PushPlus 把任务执行结果直接推到微信上，手机随时看。

PushPlus 是什么

PushPlus 是一个微信推送服务，通过 HTTP 请求就能把消息推送到你的微信。不需要装 App，不需要自建微信机器人，注册后拿一个 token，调接口即可。

核心流程：

你的脚本 -> HTTP POST -> PushPlus 服务器 -> 微信模板消息

免费版每天 200 条，个人用完全够。注册地址官网搜一下就有，登录后在"一对一推送"页面复制你的 token。

获取 Token

登录 PushPlus 后，在用户中心找到 token，是一串 32 位左右的十六进制字符串。把它配置到环境变量里，别硬编码在代码中。

export PUSHPLUS_TOKEN="你的token"

Python 推送代码封装

封装一个推送函数，支持标题和内容，返回推送结果。直接用 requests 库，没有就装一下。

import os
import requests
import json

def push_wechat(title, content, token=None):
    """
    通过 PushPlus 推送消息到微信
    :param title: 消息标题，最长 100 字符
    :param content: 消息内容，支持 HTML，最长 30KB
    :param token: PushPlus token，默认从环境变量读取
    :return: bool 是否推送成功
    """
    if token is None:
        token = os.environ.get("PUSHPLUS_TOKEN")
        if not token:
            print("[PushPlus] 未配置 token，跳过推送")
            return False

    url = "http://www.pushplus.plus/send"
    payload = {
        "token": token,
        "title": title,
        "content": content,
        "template": "html"  # 可选 html, txt, json, markdown
    }
    headers = {"Content-Type": "application/json"}

    try:
        resp = requests.post(url, json=payload, headers=headers, timeout=10)
        result = resp.json()
        if result.get("code") == 200:
            print(f"[PushPlus] 推送成功: {title}")
            return True
        else:
            print(f"[PushPlus] 推送失败: {result.get('msg')}")
            return False
    except Exception as e:
        print(f"[PushPlus] 请求异常: {e}")
        return False

注意几个点：

  • 超时设 10 秒，避免推送服务挂掉拖死主任务
  • 返回 code 为 200 才算成功，其他都是失败
  • token 从环境变量读，方便多机器部署

标题命名规范

推送标题是你在微信上第一眼看到的东西，必须包含足够信息。建议统一格式：

[项目名] 任务状态 - 时间

比如：

[量化策略] 日线信号计算完成 - 2024-06-15 15:30
[数据备份] 执行失败 - 2024-06-15 02:00

加前缀的好处：

  1. 微信通知列表里一眼区分来源
  2. 多个任务共用手机时不混淆
  3. 失败信息更醒目，可以加 emoji 强化

封装一个标题生成函数：

from datetime import datetime

def build_title(project, status="成功", with_time=True):
    """
    生成统一格式的推送标题
    :param project: 项目名，如 "量化策略"
    :param status: 状态，成功/失败/警告
    :param with_time: 是否附加时间
    """
    if with_time:
        now = datetime.now().strftime("%Y-%m-%d %H:%M")
        return f"[{project}] {status} - {now}"
    return f"[{project}] {status}"

推送内容格式设计

内容是 HTML 格式，可以排版。别发一大段纯文本，微信上阅读体验差。推荐用表格 + 关键字段。

def build_content(items):
    """
    构建 HTML 格式推送内容
    :param items: dict, 键值对展示在表格中
    :return: HTML 字符串
    """
    rows = "".join(
        f"<tr><td style='padding:6px 12px;border:1px solid #eee'>{k}</td>"
        f"<td style='padding:6px 12px;border:1px solid #eee'>{v}</td></tr>"
        for k, v in items.items()
    )
    return f"""
    <table style='border-collapse:collapse;font-size:14px'>
        {rows}
    </table>
    <p style='color:#999;font-size:12px'>发送时间: {datetime.now().strftime('%Y-%m-%d %H:%M:%S')}</p>
    """

对于量化任务，内容里至少包含：

  • 运行时长
  • 处理数据量
  • 关键结果指标
  • 异常信息（如果有）

示例：

content = build_content({
    "运行环境": "生产服务器",
    "数据范围": "2024-01-01 ~ 2024-06-14",
    "信号数量": 12,
    "多头信号": 7,
    "空头信号": 5,
    "运行耗时": "3分25秒",
})

成功 / 失败不同推送策略

任务成功和失败，推送策略应该不一样。核心原则：

成功： 推送简略信息，确认任务正常即可 失败： 推送详细错误信息，附带堆栈或关键日志

因为失败时你需要更多信息来定位问题，而成功时只需要确认"它跑了"。

import traceback

def run_task_with_push(task_func, project, *args, **kwargs):
    """
    包装任务函数，自动推送执行结果
    :param task_func: 任务函数
    :param project: 项目名，用于标题
    :return: 任务返回值
    """
    start_time = datetime.now()

    try:
        # 执行任务
        result = task_func(*args, **kwargs)
        elapsed = (datetime.now() - start_time).total_seconds()

        # 成功推送
        title = build_title(project, "✅ 执行成功")
        content = build_content({
            "状态": "成功",
            "耗时": f"{elapsed:.1f} 秒",
            "结果摘要": str(result)[:500] if result else "无返回值",
        })
        push_wechat(title, content)
        return result

    except Exception as e:
        elapsed = (datetime.now() - start_time).total_seconds()
        error_detail = traceback.format_exc()

        # 失败推送，带完整堆栈
        title = build_title(project, "❌ 执行失败")
        content = build_content({
            "状态": "失败",
            "耗时": f"{elapsed:.1f} 秒",
            "错误类型": type(e).__name__,
            "错误信息": str(e),
        })
        # 堆栈信息放表格后面，用代码块展示
        content += f"<pre style='background:#f5f5f5;padding:10px;font-size:12px;overflow-x:auto'>{error_detail}</pre>"
        push_wechat(title, content)

        # 重新抛出异常，让上层逻辑决定是否重试
        raise

用起来很简单：

def my_daily_task():

实战：定时任务集成

配合 schedule 库或系统 crontab 使用。这里用 schedule 举例，适合脚本内自调度：

import schedule
import time

def job_wrapper():
    # 每天 15:30 执行策略计算
    run_task_with_push(calculate_daily_signals, "日线策略")

# 周一到周五 15:30 执行
schedule.every().monday.at("15:30").do(job_wrapper)
schedule.every().tuesday.at("15:30").do(job_wrapper)
schedule.every().wednesday.at("15:30").do(job_wrapper)
schedule.every().thursday.at("15:30").do(job_wrapper)
schedule.every().friday.at("15:30").do(job_wrapper)

while True:
    schedule.run_pending()
    time.sleep(30)

如果用 crontab，直接写：

30 15 * * 1-5 cd /path/to/project && python main.py >> logs/cron.log 2>&1

然后在 main.py 里同样调用 run_task_with_push 即可。

进阶：限流与重试

PushPlus 免费版有频率限制，短时间大量推送可能被限流。如果你的任务频繁执行（比如分钟级），建议加个简单限流：

import time

_last_push_time = 0
_min_interval = 5  # 两次推送最小间隔 5 秒

def push_wechat_rate_limited(title, content, **kwargs):
    global _last_push_time
    now = time.time()
    wait = _min_interval - (now - _last_push_time)
    if wait > 0:
        time.sleep(wait)
    result = push_wechat(title, content, **kwargs)
    _last_push_time = time.time()
    return result

另外，推送失败时（比如网络抖动），可以重试一次：

def push_with_retry(title, content, retries=2):
    for i in range(retries):
        if push_wechat(title, content):
            return True
        time.sleep(2)
    return False

总结

这套方案的核心价值：

  1. 零成本：PushPlus 免费额度够个人用
  2. 零依赖：只需要 requests 库，不需要额外服务
  3. 即插即用：封装好函数后，任何任务包一层就能推送

把 push_wechat、build_title、build_content、run_task_with_push 这几个函数放到一个 notify.py 模块里，所有脚本共用，维护成本极低。

推送通知不是目的，让任务结果真正被看到才是。定时任务 + 微信通知组合起来，你的策略运行状态就尽在掌握了。
